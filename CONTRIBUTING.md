# Contributing to Keel

This repository currently contains product and engineering specifications, not an implemented service. Use the phase gates and acceptance criteria in [`docs/CHECKLIST.md`](docs/CHECKLIST.md) as the source of delivery scope.

For a proposed change, state the checklist IDs, affected trust boundaries/data flows, migration and rollback implications, security/privacy impact, validation evidence, and any unresolved assumptions. Keep each pull request reviewable and avoid claiming targets or planned controls have been implemented without evidence.

No software license has been selected. Public visibility does not grant reuse rights; request permission before reusing repository content.

# K8.11/K8.2 slice 18: service-principal directory over HTTP

Related to #70 and the K8.2 track. The key store proved lifecycle and
rotation; this slice answers "which keys exist": owner/admin-visible
service-principal resolution and key listing with full lifecycle
timestamps, on two unmounted routes. No route is mounted.

## Contract

- Migration `0080_identity_key_directory`:
  `service_principal_org` (org resolution, empty when unknown) and
  `keys_for_service_principal` (keys with prefix, timestamps and
  use-stamps, rows only for owner/admin viewers) — both
  `keel_identity`-gated SECURITY DEFINER reads, no table grants.
- `internal/auth/postgres`: `ServicePrincipalOrg` (`unknown`→
  `ErrNotFound`) and `KeysForServicePrincipal` (transparent row
  mapping, `[]` when unauthorized or empty).
- `internal/auth/httpapi/apikeys.go` addition: `GET
  /v1/auth/service-principals/{sp}/keys` resolves the caller, maps
  the SP to its org, enforces owner/admin visibility (`404` for
  strangers and unknown principals, `403` for members), then serves
  `{keys: [{key_id,prefix,created_at,expires_at?,revoked_at?,
  last_used_at?}]}` with RFC 3339 timestamps.

## Verified

- `go vet ./internal/auth/...` and `gofmt` clean;
  `go test ./internal/auth/...` pass, including mapping groups
  (owner sees keys, stranger 404, member 403, bad id 400).
- Migration applied live through the runner (`0080` ledgered).
- In-container against real capability roles:
  `--- PASS: TestPostgreSQLIdentityAPIKeys` now also proves org
  resolution, unknown-principal refusal, owner-visible full key set
  with lifecycle flags, and stranger invisibility;
  `--- PASS: TestHTTPAPIKeysLifecycleAgainstPostgres` extended with
  list (keys shown) and stranger-list `404`.
- All earlier suites pass in the same runs.

## Limits

- No key search/filter, no per-key metadata beyond the lifecycle
  timestamps, no scopes or metering, no audit trail, no mounts.

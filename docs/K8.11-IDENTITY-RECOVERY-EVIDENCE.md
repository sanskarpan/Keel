# K8.11 slice 2: password recovery with rotation and session revocation

Related to #70 (K8.11 partial; does not close it). Recovery closes the
takeover boundary left open by slice 1: an active principal records a
bounded reset, then one atomic call consumes the token, replaces the
credential and revokes every live session. Owner MFA, HTTP routes and
rate limiting stay open under #70.

## Contract

- Domain: third purpose `identity-password-reset-v1` in `token.go`
  (purpose-separated from session and verification digests) plus
  `ValidateResetTTL` in `session.go` sharing the 5 min - 24 h one-shot
  window. No raw token, email or password is stored.
- Migration `0066_identity_password_recovery_rotation`:
  - forced-RLS `keel_meta.identity_password_resets` (one unconsumed reset
    per principal, globally unique 32-byte digest, `expires_at>requested_at`
    window, `consumed_at` shape), same REVOKE-ALL + schema-owner policy
    pattern as the four slice-1 tables, with a pending-to-consumed guard
    trigger.
  - `record_identity_password_reset` gated on `keel_identity`: only
    `active` principals record (`not_active` otherwise), 24-hour SQL
    window with Go-enforced 5-minute floor, global `token_reuse`, and
    resend replacing only the unconsumed row.
  - `rotate_identity_credential(token, hash)` atomic: locks the reset row,
    consumes it exactly once (`unknown`/`duplicate`), enforces expiry
    (`expired`), requires an `active` principal (`principal_inactive`),
    validates the `$argon2id$` prefix, bumps `version=version+1` with a
    changed hash, then revokes every live session. Returns
    (`rotated`, principal) only on success.
  - `revoke_all_identity_sessions(principal)` returning the revoked count
    for owner lockout; zero is valid.
  - `guard_identity_credentials_row` replaced (forward repair pattern):
    deletes refused, direct writes refused, and UPDATE allowed only for
    same principal/created with `version=old+1` and a changed bounded
    hash. Bootstrap INSERT is unaffected (BEFORE UPDATE OR DELETE only).
- `internal/auth/postgres`: `RecordPasswordReset` (maps `not_active` to
  `ErrNotVerified`, `token_reuse` to `ErrTokenReuse`),
  `RotateCredential` (transparent `rotated`/`unknown`/`duplicate`/
  `expired`/`principal_inactive` outcomes, transport errors only),
  `RevokeAllSessions` (count). Per-call transactions, no shared state.
- `Makefile` `local-identity-test` now runs `TestPostgreSQLIdentity*`
  (both lifecycle and recovery tests).

## Verified

- `go test ./internal/auth/`: pass, including the new reset purpose in
  the purpose-separation test.
- Migration applied live through the runner:
  `keel_meta.schema_migrations` records 0066; the resets table exists.
- `go test -c ./internal/auth/postgres` run inside the PostgreSQL
  container against the real capability roles
  (`KEEL_TEST_IDENTITY_DATABASE_URL` as `keel_local_identity`):
  `--- PASS: TestPostgreSQLIdentityBootstrapAndSessionLifecycle` and
  `--- PASS: TestPostgreSQLIdentityRecoveryAndRotation`.
  The recovery test proves on a real database: pending principals get
  `ErrNotVerified` on reset; verified principal mints two live sessions;
  under-min TTL rejected; `recorded` then cross-principal `token_reuse`;
  atomic `rotated` with the right principal id; repeat rotate is
  `duplicate`; unrecorded digest is `unknown`; backdated request rotates
  as `expired`; credential `version` is 2 afterwards; old password fails
  and new password verifies against the stored Argon2id hash; both
  pre-rotation sessions resolve but judge invalid; revoke-all with no
  live sessions returns 0; two fresh sessions then revoke-all returns 2
  and both judge invalid; FORCE RLS on the resets table with no grants
  to any non-owner across all five tables; `keel_local_app` denied on
  the reset function and `keel_local_identity` denied direct reset
  reads.
- `go vet ./internal/auth/...` and `gofmt` clean for the touched files.

## Limits

- No HTTP routes: record/rotate/revoke-all are repository calls only.
- No owner MFA, no rate limiting or lockout counters, no reset-email
  transport, no pepper provisioning, no audit trail: all still open
  under #70.
- Reset window is fixed (5 min - 24 h Go, 24 h SQL ceiling); cooldown
  between resends and max-attempt policy need a later explicit decision.
- Tenant binding still deferred to K8.1/K8.2; `tenant_id` unused here.

# K5.5.2 Tenant cost dashboard read API

Issue [#329](https://github.com/sanskarpan/Keel/issues/329) exposes the tenant cost read model from [K5.5.1](K5.5-COST-DASHBOARD.md) as a documented read surface.

## Routes

| Method and path | Behaviour |
|---|---|
| `GET /v1/costs` | the authenticated tenant's current budget-period cost breakdown |
| `GET /v1/costs/{period_id}` | one budget-period cost breakdown for the authenticated tenant |
| `GET /v1/costs/{period_id}/entries` | the bounded per-inference cost rows of one period, `limit` defaults to 25 and is capped at 100 |

The routes and their schemas are documented in [`contracts/openapi/openapi.yaml`](../../contracts/openapi/openapi.yaml) and a contract check fails when a served route is not documented.

## Identity and authorization

The handler accepts a tenant identity only from trusted authentication context. A tenant identifier in a header, path or body is never considered, and the authenticated tenant is the only tenant the reader is asked for.

Every read needs an explicit authorization decision for the tenant cost view. A denied view is answered with `404` and a `resource_not_found` code, so a caller cannot use the response to learn whether cost data exists. An authorization service that cannot answer is answered with `503` and no data. A missing identity is `401`.

## Response contract

A breakdown returns the period identity and bounds, the scope, the currency, the hard limit, the confirmed, carried, estimated, unknown and outstanding amounts in integer micro-USD, whether the account is blocked, and the watermark of account version, ledger entry count and newest ledger entry time. The entry rows return the tenant-scoped opaque inference identifier, the cost classes of that inference, its liability state and its last activity time.

The response contains no prompt, response, model or provider identifier, rate-card contents, principal binding, request digest, ledger source reference, ledger reason or customer content. Responses are `Cache-Control: private, no-store`, carry the standard security headers, and are logged with the shared HTTP correlation middleware so a request can be correlated without adding identifiers to the body.

## Limits

The handler is a read surface, not a mounted service: no runtime serves it yet, because identity resolution and authorization adapters are not wired. It does not render a dashboard, alert, invoice or entitlement, does not convert currency, and does not expose a period the tenant cannot read. The bounded entry rows are a page of the period's inferences, not a complete export, and the endpoint does not paginate beyond the limit.

## Validation

- Handler tests cover a missing identity, a denied view, an unavailable authorization decision, the current-period read, the named-period read, an invalid period identifier, an invalid limit, an unbounded limit, an unexpected query parameter, a missing period, and an unsafe method.
- The cost breakdown response is asserted field by field so a new field cannot appear without a decision.
- A contract check loads the OpenAPI document and fails when a served cost route is missing or renames its operation.
- Merge and contract-run evidence will be recorded in `docs/CHECKLIST.md` after the implementation PR is merged.

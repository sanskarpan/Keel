# K8.11 slice 4: bounded login lockout

Related to #70 (K8.11 partial; does not close it). Recovery closed the
takeover boundary; this slice closes the guessing boundary: five
consecutive wrong passwords lock the principal for 15 minutes, success
clears the count, and the login surface reports the lock with `429` and
`Retry-After` instead of leaking it as a credential verdict.

## Contract

- Migration `0067_identity_login_lockout`: forced-RLS
  `identity_login_throttle` (one row per principal, monotonic count,
  15-minute staleness window, `locked_until` shape), capability-gated
  `record_identity_login_failure` (`counted`/`locked`/`unknown_principal`;
  expired locks and failures older than 15 minutes restart at one;
  attempts while locked change nothing, so attackers cannot stretch the
  lock), `reset_identity_login_throttle` (success deletes the row, count
  returned), and `identity_throttle_for` (count + lock expiry read).
  Migration `0068_identity_throttle_guard_repair` forward-repairs the
  guard, which had refused the fresh-count reset its own decay branch
  requires; only that exact transition may move `first_failure_at`.
- `internal/auth/postgres`: `RecordLoginFailure` (`unknown_principal`
  to `ErrNotFound`), `ResetLoginThrottle` (count), `ThrottleFor`
  (count + expiry, zero values when unrecorded).
- `internal/auth/httpapi` login: pre-checks the throttle (`429 locked`
  + `Retry-After` when the database clock still shows a lock), records
  each wrong password (fifth consecutive failure becomes `429`; earlier
  ones stay `401 invalid_credentials` alongside unknown emails and
  pending principals), and best-effort clears the count on success so a
  throttle-table outage cannot lock out a principal that proved its
  password.

## Verified

- `go vet ./internal/auth/...` and `gofmt` clean;
  `go test ./internal/auth/...` pass, including new handler unit groups
  (pre-locked `429` + `Retry-After`, fifth-failure `429` vs earlier
  `401`) and constructor checks.
- Migrations applied live through the runner (`0067`, `0068` ledgered).
- In-container against real capability roles:
  `--- PASS: TestPostgreSQLIdentityLockout` — four `counted`, fifth
  `locked`, locked attempt returns `locked` with byte-identical expiry
  (no stretching), reset returns 1 then throttle reads zero, empty reset
  returns 0, unknown principal is `ErrNotFound`, backdated failures
  decay to count 1 unlocked, FORCE RLS on with no direct grants, and
  `keel_local_app` / `keel_local_identity` denials.
- `--- PASS: TestHTTPIdentityLifecycleAgainstPostgres` extended: four
  wrong passwords are `401`, the fifth is `429 locked` with
  `Retry-After`, and the correct password stays `429` while locked.
- The guard bug (`identity throttle identity is immutable` on decay)
  was caught by the live test before commit and fixed forward per the
  migrations README; re-run is green.

## Limits

- No per-IP or global throttling, no lockout notification, no admin
  unlock endpoint, no audit trail: still open under #70.
- Constants (5 attempts, 15-minute lock/decay) are SQL-side with no
  operator policy table; a later slice may need versioned policy.
- Reset is best-effort on success; a throttle outage is not surfaced to
  the caller. No MFA, no tenant binding, no mounted routes.

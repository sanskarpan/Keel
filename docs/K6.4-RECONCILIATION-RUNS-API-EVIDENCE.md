# K6.4 slice: reconciliation run history API

Issue #422 (parent #49, checklist item K6.4). PR #423 merged as
`1d9d22a8f4b66bc9aed15ca753aa1d5bb22f2c49`; contract CI #677 passed on reviewed head
`680157d9343db0cd8b324df2009fd35c4d350015`. This slice exposes recent reconciliation
runs with their audited repair totals on the unmounted operator API.

## Contract

- Migration `0061` adds operator-gated `list_webhook_reconciliation_runs(limit)`: recent runs
  newest-first with run ID, operator principal, from/cursor watermarks, scanned/gap/missing
  counts and summed repaired/skipped totals, bounded to 1-100 rows. No event IDs, endpoint,
  URL, payload or receiver content.
- Go adds `ReconciliationRunSummary` with store validation and `Store.ReconciliationRuns` over
  the operator capability, plus `GET /v1/webhooks/reconciliation-runs` on the unmounted handler
  reusing the injected principal/authorization pattern, capped `limit` query and fixed problem
  codes.
- Coverage includes plan-then-repair totals, newest-first ordering, tenant isolation, limit
  bounds, capability and direct-table denial, handler auth/limit/error mapping and leak checks.

## Limits

No mounted route, production identity, scheduler integration, reconciliation UI, provider
observation or repair behavior change.

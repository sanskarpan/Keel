# K8.11/K8.2 slice 20: MFA step-up for ownership transfer

Related to #70 and the K8.2 track. Transfer is the highest-risk single
action in the identity surface: a password-only account takeover must not
be enough to steal an organization. The transferring owner must hold a
registered WebAuthn credential; otherwise the call fails closed with
`mfa_required` and changes nothing. Self-transfer stays a no-op.

## Contract

- Migration `0081_identity_transfer_mfa_stepup` replaces
  `transfer_organization_ownership` with a version that checks for any
  registered WebAuthn credential on the actor after the authorization
  checks and before the swap (`mfa_required` otherwise). No new tables.
- `internal/auth/postgres`: `ErrMFARequired` sentinel mapped from
  `mfa_required`.
- `internal/auth/httpapi/invites.go`: transfer maps it to `403
  mfa_required`.

## Verified

- `go vet ./internal/auth/...` and `gofmt` clean;
  `go test ./internal/auth/...` pass, including the new mapping case.
- Migration applied live through the runner (`0081` ledgered).
- In-container against real capability roles:
  `--- PASS: TestPostgreSQLIdentityInvitesAndTransfer` extended — a
  second org whose owner holds no key is refused with `ErrMFARequired`,
  key enrollment unblocks the same call to `transferred`;
  `--- PASS: TestHTTPInviteTransferAndSwitchAgainstPostgres` extended
  — transfer without MFA answers `403 mfa_required`, enrollment
  unblocks `204`.
- All earlier suites pass in the same runs.

## Limits

- Presence of any key suffices; no per-ceremony proof, no
  key-age/recency policy, no per-org MFA enforcement flag.
- No ceremony HTTP for the enrollment path used by tests beyond the
  existing WebAuthn endpoints; the step-up check trusts the stored
  credential rows that ceremony verification maintains.

# K5.1.1 durable order state SSE

This is the first implementation slice of [K5.1](https://github.com/sanskarpan/Keel/issues/39), tracked by [issue #270](https://github.com/sanskarpan/Keel/issues/270). It exposes durable order state events; transient model tokens and production runtime/auth wiring remain outside this slice.

## Contract

- `GET /v1/orders/{order_id}/stream` reuses the trusted identity context and per-order `CanReadOrder` authorization boundary. Tenant and order scope are never taken from a tenant header, query parameter, body, or stream cursor.
- The cursor is `state:<order-id>:<tenant-sequence>`. It is bound to one order so a cursor cannot be copied between two order streams. The durable PostgreSQL sequence remains authoritative across reconnects and API replica replacement.
- PostgreSQL reads a bounded page of at most 100 typed state rows plus the oldest retained sequence and durable high-water mark in one repeatable-read transaction. Only event ID, aggregate ID, version, update kind, status, and sequence are returned; raw JSON payloads are not forwarded.
- The 24-hour state-feed retention boundary is authoritative. A cursor older than retained history receives `resync_required` and the client must fetch the current authorized order snapshot before reconnecting. If all rows expired, the durable counter still detects the gap.
- Updates for other orders advance the tenant sequence through a cursor-only event. Their aggregate IDs and payloads are never sent on this order stream.
- Polling is bounded to 100 rows per read and one read per second while idle. Heartbeats are SSE comments every 15 seconds. The handler exits on request cancellation. Responses are private/no-store and disable common reverse-proxy buffering.
- The route accepts only an optional `cursor` query parameter and the standard `Last-Event-ID` header. If both are supplied they must match. Malformed, duplicate, cross-order, or future cursors fail before the stream starts.

## Verification scope and limits

Unit coverage exercises cursor validation, trusted tenant propagation, per-order filtering, cursor checkpoints, future cursors, retention resynchronization, and canceled requests. PostgreSQL integration coverage exercises bounded pagination, cursor resume, typed payloads, tenant RLS isolation, and invalid page limits.

This handler is not attached to a production API process: authentication middleware, deployment routing, CORS policy, and customer traffic remain gated by K0. Cross-origin CORS remains disabled unless a future deployment explicitly configures an origin allowlist. Slow-client write deadlines, per-client queue budgets, reconnect snapshots, and interrupted model token delivery are tracked in [K5.2](https://github.com/sanskarpan/Keel/issues/40). No model executor currently emits a client-visible token stream, so no token or completion events are claimed here.

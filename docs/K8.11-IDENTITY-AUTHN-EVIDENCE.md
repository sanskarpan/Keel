# K8.11/K8.2 slice 18: unified authentication and whoami

Related to #70 and the K8.1/K8.2 tracks. Sessions and API keys previously
authenticated through separate paths; this slice unifies them into one
identity shape with the tenant attached, which is the composition point
for a serving gateway. The package stays unmounted.

## Contract

- `internal/auth/httpapi/authn.go`: `Identify` resolves one bearer
  credential, preferring sessions — a live session with an active org
  yields `{session, principal, org, tenant}`; otherwise a valid API-key
  digest yields `{api_key, service principal, org, tenant}`; everything
  else fails closed with no identity. `GET /v1/auth/whoami` serves the
  shape back (`kind`, `org_id`, `tenant_id`, plus the subject id) and
  `401`s the unidentified.

## Verified

- `go vet ./internal/auth/...` and `gofmt` clean;
  `go test ./internal/auth/...` pass, including `Identify` preference
  and `whoami` kind matrices (session, key, revoked/unknown/errored,
  bearerless).
- `--- PASS: TestHTTPWhoamiAgainstPostgres` in-container against the
  real store: unswitched session resolves nothing, switched session
  resolves to its org, an issued bearer key resolves to the same org
  as `api_key`.
- All earlier suites pass in the same runs.

## Limits

- Helper plus one probe route; no gateway consumes it and no
  `WithTenantTx` call site exists yet.
- No per-request tenant switching beyond session switch, no scope
  narrowing for keys, no audit trail.

# K6.3 slice: allowlisted webhook payload source

Issue #364 (parent #48, checklist item K6.3). PR #366 merged as
`4a084a23c96e1c8adc71b5529eef00244f0d53de`; contract CI #600 passed on reviewed head
`93d26087d11a73ad538ca37ca2a747261227b3b2`. This slice gives the delivery worker its first production body source: the
canonical, privacy-safe outbox envelope for the delivery's event. It does not add a delivery
producer, event fanout, worker process wiring or per-event webhook body schemas.

## Body contract

The signed bytes are `event_outbox.safe_envelope::text`: canonical JSON produced by PostgreSQL
from the allowlisted envelope written in the order transaction. The fields are
`schema_version`, `event_id`, `tenant_id`, `aggregate_id`, `aggregate_version`, `event_type`,
`occurred_at` and optional `traceparent`. It contains no external reference, supplier identity,
line item, amount, evidence digest or raw `order_events` content. The body is independent of the
endpoint, subscription revision, delivery ID, attempt ID and timestamp, so retries and replays of
one event receive identical bytes.

`safe_envelope` is `jsonb`, so the bytes are the canonical text at read time rather than the
original producer byte string. Formatting is stable for a stored row within a PostgreSQL version;
it is not a promise that arbitrary JSON re-rendering preserves whitespace.

## Read path

Migration `0046_webhook_payload_source` adds
`keel_meta.read_webhook_delivery_body(delivery_id)`:

- Requires membership in `keel_webhook` and derives the tenant from
  `keel_private.current_tenant_id()`, never from the delivery or receiver.
- Accepts only the bounded delivery ID and resolves the event from `webhook_deliveries`; the
  event must be a canonical UUID that exists in `event_outbox` for the same tenant.
- Returns `r_event_id`, `r_content_type=application/json` and `r_body bytea`, bounded to
  1 byte-1 MiB.
- Returns no row for a missing delivery, non-UUID event or missing outbox envelope, and raises a
  fixed error for an out-of-bound body.
- Runs with a fixed `search_path`, is owned by `keel_schema_owner`, revokes `PUBLIC`, and grants
  execute only to `keel_webhook`.

`event_outbox` is forced through RLS, so the migration adds the schema-owner read policy while
keeping the existing app/worker tenant policies. The webhook role still has no direct `SELECT`
on `event_outbox`, `webhook_deliveries` or any order table. No URL, key, signature, receiver
response or private event fact is returned.

## Worker integration

`worker.PayloadSource` now takes the trusted `tenancy.TenantID` explicitly. `Runner.Run` passes
the same tenant it used for leasing, and `Store.Payload`:

- validates the tenant, delivery and delivery/tenant identity agreement;
- requires a canonical UUID event ID;
- starts a tenant transaction, calls the read function and verifies the returned event ID and
  content type;
- enforces the 1 MiB bound again in Go;
- returns `ErrInvalidDelivery` for missing, oversized, mismatched or malformed bodies so the
  worker records a permanent failure, while database failures remain retryable.

An event without a committed outbox envelope is therefore a permanent data-integrity failure.
A future producer must commit the event and outbox row before claiming deliveries.

## Verification

Coverage runs against a fresh PostgreSQL database with migrations through `0046`:

- exact canonical bytes and byte equality across repeated reads;
- cross-tenant lookup denial and delivery/tenant mismatch rejection;
- missing payload and oversized payload as permanent failures;
- unset tenant context, direct `event_outbox` select and non-webhook function execution denied;
- retryable mapping for an unreachable database;
- worker interface and package tests.

Commands: `go test -count=1 ./internal/delivery/webhook/...` and
`go vet ./internal/delivery/webhook/...` with the local webhook, app and admin DSNs.

## Still open

No webhook body schema is published per event type, and integrations cannot receive event
payload facts beyond the allowlisted envelope. There is no delivery producer/fanout, no worker
process registration, no tenant scheduling/quota and no metric contract. Replay execution and
the operator surface remain separate K6.3 work.

# K4.2 offline policy and privacy boundary

Issue [#182](https://github.com/sanskarpan/Keel/issues/182) implements a first isolated K4.2 slice under parent [#32](https://github.com/sanskarpan/Keel/issues/32). It does not complete K4.2 or enable live inference.

`internal/ai/policy` accepts only the exact ID and version of an immutable code-owned bundle. A bundle pins prompt template ID/version, provider profile and model, input/output bounds, tool allowlist version/content, and scrubber version. Registry construction deep-copies values, validates template variables and allowlists, canonicalizes unordered lists, and calculates a stable SHA-256 digest over deterministic JSON. The only registered provider/model profile is an offline fake, and the only registered tool policy is the empty `tools.none.v1` set; unknown providers/models and all executable tools are rejected. A prepared call carries that snapshot; invocation requests cannot override provider/model, generation limits, tool policy, prompt template, or scrubber.

Prompt variables are typed with source provenance and sensitivity classification. Callers must derive those fields server-side; they must never come from tenant request data. Unknown source, explicitly sensitive or unclassified segments, malformed UTF-8, unknown variables, missing variables, unknown policy versions, and input over the configured byte limit fail closed before the provider seam. Template expansion is one pass, so variable content is never interpreted as template syntax.

The pinned `keel.scrubber.high-confidence.v1` implementation replaces recognized email addresses, US SSNs, E.164 phone numbers, bearer credentials, and common prefixed API-key forms. Static prompt templates containing these patterns are rejected. This is narrow defense in depth, not a general PII detector: it does not claim recall for names, addresses, arbitrary account identifiers, or every credential format. Classification remains a trusted server responsibility.

`SafePrompt` and `Call` suppress contents in normal and Go-syntax formatting. The package-private provider seam receives only a prepared call, emits fixed structured outcome metadata, and discards provider error details. Tests use a fake provider and the production JSON logger; they verify redaction, no dispatch after rejected/canceled inputs, stable policy digests, immutable allowlists, template-injection resistance, and absence of prompt/response canaries in logs.

This package has no live provider adapter, registered deployment bundle, API route, database schema, prompt persistence, context vault, tracing, cache, fallback, streaming, or tool execution. It is not safe to wire to a production provider until authenticated read-only tools (K4.1), durable spend admission (K4.3), leased execution limits (K4.4), K0 runtime composition, and retention/tracing controls (K5.4) are implemented and qualified. Provider-input text remains sensitive even after pattern replacement and must not be logged or retained by future adapters without an approved policy.

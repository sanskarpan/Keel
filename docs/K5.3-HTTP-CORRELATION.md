# K5.3.1 safe HTTP correlation boundary

This is the first implementation slice of [K5.3](https://github.com/sanskarpan/Keel/issues/41), tracked by [issue #278](https://github.com/sanskarpan/Keel/issues/278). It adds a shared HTTP request/trace correlation boundary and wires it into the order read handler. It does not provide end-to-end distributed tracing.

## Contract

- The server generates a cryptographically random RFC 4122 UUIDv4 request ID, a trace ID when no usable parent exists, and a fresh server span ID for every request.
- Only a single valid W3C traceparent version `00` is accepted as a parent. Malformed, repeated, unsupported-version, uppercase, or zero-ID values are treated as absent and replaced with fresh server trace context; they do not cause request rejection.
- The shared `internal/platform/tracecontext` package validates and formats traceparent version `00` for both HTTP and order event metadata. `TraceparentFromContext` returns the current server span context for downstream instrumentation; no producer, workflow, model, or delivery consumer is wired by this helper.
- The validated request ID, trace ID, server span ID, parent span ID, and trace flags are available through typed request context. `X-Request-ID` returns the server-generated request ID; caller-provided request IDs are ignored.
- Completion logs contain a static message, router pattern, request ID, trace ID, HTTP status, and duration. Concrete paths, query strings, body data, tenant/principal identifiers, authorization, cookies, and incoming traceparent text are not logged.
- The response-writer adapter preserves `http.Flusher` and `ResponseController` operations through `Unwrap`, including the write-deadline support used by order SSE.
- Problem response `request_id` is the same request ID returned in the response header and recorded in the completion log.

## Verification scope and limits

Tests cover traceparent parsing, malformed/repeated parent fallback, random request IDs, context fields, status capture, route-pattern logging, absence of concrete URL/query data, and response-controller deadline/flush compatibility.

This slice wires the order read HTTP handler only. Other HTTP families, database/query spans, event/outbox links, workflow propagation, model and provider spans, delivery/broker headers, exporters/collectors, sampling, and production runtime configuration remain future K5.3 work. Trace IDs are correlation metadata, not proof that an exporter or distributed trace is running.

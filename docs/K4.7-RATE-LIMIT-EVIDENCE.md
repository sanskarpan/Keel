# K4.7 home-region rate-limit evidence

## Delivered scope

Issue #196 adds a shared Redis-backed token bucket with one atomic Lua decision per logical request. Bucket refill uses Redis server time, not application clocks, and stores milli-tokens so sub-unit refill credit survives requests that arrive before a whole token has accumulated. All API replicas in a tenant's home region use the same opaque tenant/route bucket key. HMAC-SHA256 binds the region, tenant, route and request identity without placing those identifiers directly in Redis keys. Bucket and replay keys share an opaque HMAC hash tag, so both keys occupy one Redis Cluster slot for atomic scripts. The configured key ID is part of the key namespace and rotation creates a cold bucket; operators must plan any rotation to avoid an unintended admission burst.

Each request includes a stable opaque request ID. Redis stores its exact policy/cost fingerprint and original decision for a bounded replay window. An exact replay returns that decision without consuming another token. Reusing the request ID with a changed policy, capacity, refill rate or cost is rejected. This makes a retry after an uncertain Redis response idempotent while the deduplication record is retained. Callers must reuse the same request ID for the same logical admission and allocate a fresh ID for a new admission.

Remote Redis requires TLS 1.2+, certificate verification, a password, bounded dial/read/write timeouts, a bounded pool, and exact region/home-region match. Plaintext is accepted only when explicitly enabled for a loopback synthetic Redis. Budgeted/model/sensitive routes receive an error on Redis failure and must fail closed. No local allowance is auto-created as replicas scale.

## Integration coverage

The contract workflow starts pinned Redis 8.2.3 and runs a test with two independent Go Redis clients/limiter instances against one bucket. Concurrent requests prove aggregate capacity is shared; subsequent checks cover exact request replay, conflicting request-ID reuse, cross-tenant isolation, partial refill preservation, and fail-closed behavior when Redis is unavailable. Unit validation rejects region mismatch, remote plaintext and disabled certificate verification, and verifies the shared Cluster hash tag.

## Limits and remaining parent issue gates

Redis is a soft global admission authority, not a replacement for PostgreSQL financial reservations. Managed home-region Redis provisioning, credentials/ACL delivery, network policy, failover and replication-loss measurements, capacity/connection qualification, metrics/alerts, and safe-read degraded mode remain under parent #37. In particular, no process-local fallback is provided: restart and replica churn would make a local allowance difficult to bound fleet-wide during a Redis outage. Model, sensitive-write and budgeted routes remain fail-closed until an operator-approved degradation policy is separately proven. This slice provides a Redis test client profile and package integration, not customer traffic wiring.

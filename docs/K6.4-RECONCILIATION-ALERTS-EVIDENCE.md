# K6.4 slice: reconciliation alert rules

Issue #439 (parent #49, checklist item K6.4). PR #440 merged as
`b242ef1a0d4268b1f0c79f6c5e00c8088f7d7581`; contract CI #699 passed on reviewed head
`b9811847abc7a761c5e9aa6e61ea3b2720dd9948` (two earlier attempts hit the known unrelated

reconciliation metrics and four source-controlled local Prometheus alert rules. No migration
was needed.

## Contract

- `Recorder.ObservePlanFailure/ObserveRepairFailure` feed a new fixed
  `keel_webhook_reconciliation_errors_total{op="plan"|"repair"}` series; the label-surface
  test now pins the six outcome plus two operation series.
- The store observer interface gains the two failure methods, fired only for operational
  failures after request validation; existing callers default to no observer.
- `deploy/monitoring/prometheus/keel-webhook-reconciliation-alerts.yaml` adds four warning
  rules (plan errors, repair errors, repair skips, gap rate), mounted in Compose and loaded
  by the local Prometheus profile. Expressions use only fixed series/labels.
- Coverage includes series rendering, failure observation counts with exact 1/1 assertions,
  observer clearing, and the full existing plan/repair suites.

## Limits

No Alertmanager, notification delivery, paging ownership, Grafana JSON, hosted dashboard, SLO
burn-rate qualification or production deployment. Thresholds are local starting points.

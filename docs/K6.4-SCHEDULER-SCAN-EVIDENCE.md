# K6.4 slice: scheduler dry-run scan hook

Issue #428 (parent #49, checklist item K6.4). PR #429 merged as
`dd0278f6862d866f51db3b0b1a0d4e989a893cd6`; contract CI #685 passed on reviewed head
`4ebec5e843f8cec184519d8718342cfc1c8e56b4` (earlier attempts hit the known unrelated Kafka
rebalance flake and a Temporal test-server infra flake). This slice adds an opt-in,
disabled-by-default dry-run reconciliation scan to the delivery scheduler. No migration was
needed.

## Contract

- `scheduler.Reconciler` plans one bounded dry-run page per processed tenant after its delivery
  batch; failures are isolated per tenant like delivery failures and reported separately.
  Tenants without due work are never scanned, so idle tenants advance no cursor.
- `Report` gains `ReconScanned/ReconGaps/ReconMissing/ReconFailures`, which flow into the
  worker pass log as fixed aggregate fields; observer/metric contracts are unchanged.
- Coverage includes per-tenant scan calls with tenant order, failure isolation with continued
  delivery work, disabled-by-default silence, option validation, a real-store integration test
  proving the scan records runs without creating deliveries, and updated content-free logging
  assertions.

## Limits

No runtime wires the hook: planning needs the operator capability, which the delivery worker
process deliberately does not hold. No repair calls, scheduler cadence change, UI, provider
observation or production wiring.

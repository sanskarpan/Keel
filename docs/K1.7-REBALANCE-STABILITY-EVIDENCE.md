# K1.7 slice: rebalance redelivery test stability

Issue #434 (parent #51, K1.7 crash/rebalance boundary). PR #435 merged as
`98cb60e9765cebf72202b0447b9f45b949986080`; contract CI #693 passed on reviewed head
`6f14fd5e378316a0e4af60ee5ee03ac564d73fc2`. This slice hardens
`TestPostgreSQLKafkaConsumerReplaysUncommittedDBEffectAcrossGroupRebalance` against
cross-talk and arms it with decisive failure diagnostics. No production code changes.

## Symptom

Intermittent CI failure (including three consecutive hits) with the redelivery asserting
`result={Disposition:quarantined ReasonCode:invalid_record Applied:0}` instead of `Duplicate`.
`invalid_record` is produced only by pre-inbox record-shape failures, so the redelivered bytes
necessarily differed from the first event's; the first leg always applied and asserted fine.

## Eliminated classes

- Single-message publish verified (`Publisher.RunOnce` sends at most one event; the first
  publish asserts the first event ID).
- No same-process earlier writers to the topic (the only other writer test runs later in file
  order; no `TestMain`/init publishers; no `t.Parallel`).
- No hidden offset commits (race-step `CommitInterval: 0` means synchronous explicit commits
  only; `Close` and `FetchMessage` never auto-commit; the failing commit wrapper returns
  before touching the broker).
- Deterministic decode (struct marshal, no maps) and deterministic duplicate detection, so
  identical bytes cannot change outcome between the two legs.
- Root cause (which foreign bytes, and their writer) remains open; local non-race runs pass
  8/8 and `-race` cannot run on the 32-bit local toolchain, so CI timing is implicated but
  unproven.

## Contract

- The consumer group is unique per run, so committed offsets from earlier runs, local reruns
  or shared brokers can never move this test's fetch position.
- On an unexpected redelivery outcome the test now dumps, from the admin connection only:
  quarantined coordinates with payload hashes and reasons, inbox event states, and the
  expected first-event payload hash recomputed from the canonical outbox envelope. A hash
  match proves same-bytes redelivery with failed decode; a mismatch proves foreign bytes and
  identifies their offset for the follow-up.

## Limits

No production behavior change; no proven root cause yet. If CI fails again, the diagnostic
output decides the next step instead of another blind rerun.

## Verification

- `go test -count=1` (8 local runs, isolated database plus fresh topic) green.
- `go vet` on the touched package; Linux CI covers the race detector.

# K6.2 Durable webhook delivery ledger

Issue [#338](https://github.com/sanskarpan/Keel/issues/338) under parent [#46](https://github.com/sanskarpan/Keel/issues/46) adds the durable half of the logical delivery identity: PostgreSQL now mints exactly one delivery ID per tenant event, endpoint and subscription revision, so a retried or concurrent scheduler cannot present a receiver with two deliveries of one logical effect.

## Uniqueness model

Migration `0040_webhook_deliveries` creates `keel_meta.webhook_deliveries`:

- `(tenant_id, delivery_id)` is the primary key, and `delivery_id` is additionally unique across tenants, so a receiver-visible delivery ID can never be reused by another tenant;
- `(tenant_id, event_id, endpoint_id, subscription_version)` is unique, so one logical identity owns one delivery;
- `created_at` is database-derived and immutable, which gives a retry a stable scheduling reference.

The same event delivered to another endpoint, under another subscription revision, or for another tenant is a different logical delivery and gets its own ID. Nothing in the table names a URL, a secret or an attempt.

## Claim flow

`postgres.Store.Ensure` validates the identity with the K6.2 contract, generates a candidate delivery ID and calls `keel_meta.claim_webhook_delivery` inside one tenant transaction:

- the first claim inserts the row and returns the winning ID with `created=true`;
- a later or concurrent claim hits the identity unique constraint, reads the recorded row and returns the same ID with `created=false`;
- the recorded creation time is returned both ways, so a retry schedules from the original delivery rather than from the retry time.

The candidate ID is never rewritten into an existing row: a duplicate claim returns the recorded delivery ID and discards the candidate. A concurrent test with four claimers observes exactly one creation and one recorded row.

## Access control

- A dedicated `keel_webhook` capability has no direct table privileges; the local `keel_local_webhook` login is synthetic test scaffolding.
- Both reads and writes go through the capability-gated `SECURITY DEFINER` claim function, which derives the tenant from the transaction-local authorized context and re-validates every argument.
- Forced tenant RLS applies, and direct privileges are revoked from every runtime role, including `keel_webhook`.
- Rows are immutable in this slice: any `UPDATE` or `DELETE` raises, including for the schema owner. A later slice can add a guarded transition when delivery state exists.
- A role without the capability cannot claim, and a claim outside an authorized tenant context fails closed.

## Bounds

Event IDs must match `^[A-Za-z0-9_.:-]{8,128}$`, endpoint and delivery IDs `^[A-Za-z0-9_-]{8,64}$`, the subscription revision must be between 1 and 1000000, and the tenant must be a non-zero UUID. The Go store rejects an invalid identity before opening a transaction, and the function re-checks the same rules so a direct caller cannot bypass them.

## Validation

- Unit coverage: store construction, nil store/database handling, a nil context, and zero, malformed, short or out-of-range identity fields.
- PostgreSQL coverage: create-once and duplicate claim with the same ID and creation time, tenant/endpoint/revision/event scoping, four concurrent claimers producing one row, direct select/insert/update/delete denial for the webhook role, immutable-row rejection for the schema owner, a role without the capability, invalid function arguments and a missing tenant context.
- The migration suite applies `0040` to a disposable database. `go test ./...` passes against the local stack except the known Windows-only `internal/contracts` and `internal/supplier/intake` failures, which fail identically on `main`.

## Limits

This is durable identity only. No endpoint registration, destination URL or signing secret is stored, no attempt row or response classification exists, no state transition, retry schedule, circuit breaker, exhaustion marker or lease is defined, and no worker is wired. Attempts and retry state are K6.3; reconciliation is K6.4; adversarial late/duplicate/replay qualification is K6.5; parent #46 stays open.

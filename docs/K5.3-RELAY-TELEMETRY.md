# K5.3.4 Order relay and projector telemetry

Issue [#314](https://github.com/sanskarpan/Keel/issues/314) adds optional observer hooks at the durable order relay and projector boundaries. This slice builds on validated order trace correlation in [K5.3.3](K5.3-OUTBOX-CORRELATION.md).

## Event contract

The only operation values are `outbox.publish` and `projector.process`. Outcomes are fixed: relay uses `published`, `retry_scheduled`, `blocked`, `no_work`, and `error`; projector uses `applied`, `duplicate`, `deferred`, `quarantined`, and `error`. Events contain elapsed duration capped at one hour, schema version 1 or 2 when decoded, and relay retry count capped at 100. Projector events do not include a retry count. A trace ID is included only after strict W3C traceparent parsing; schema-v1, absent, or invalid trace context produces no trace ID.

The logger observer writes only these fields. It never writes event/tenant/aggregate IDs, Kafka partition or offset, partition keys, envelope/payload content, arbitrary headers, raw errors, or caller-provided strings. No user-defined attributes are accepted. A missing observer is a no-op. Observer panics are recovered after the durable operation so they cannot change publish acknowledgment, projection persistence, or the caller's offset-commit decision. Custom observer implementations must return promptly and should be non-blocking.

## Operational use

Operators may group records by operation and outcome and compare bounded durations and relay retry counts. The optional trace ID can correlate these records with another system that already has the same validated trace context. These events do not identify an individual outbox row, prove message delivery, or replace canonical database and broker health checks. A quarantine record is correlated only by trace ID when it had a valid v2 context; use restricted canonical diagnostics for message-level investigation.

## Limits

This is a structured log/observer hook only. It does not configure an exporter, create OTel spans, add Prometheus series, wire an application runtime, establish retention/egress controls, or provide end-to-end coverage across queries, Temporal, model/provider calls, and delivery sinks. Any future exporter/runtime wiring requires its own issue, privacy review, and deployment qualification. The normal relay retry, ordering, projector transaction, and Kafka offset policy remain authoritative.

## Validation

- Unit tests verify event field sanitization and bounds, outbox v1/v2 trace behavior, retry trace correlation, projector v1/v2 behavior, and observer panic isolation.
- Existing PostgreSQL/Kafka contract tests continue to validate immutable envelope redelivery and offset safety independently of optional telemetry.
- Merge and contract-run evidence will be recorded in `docs/CHECKLIST.md` after the implementation PR is merged.

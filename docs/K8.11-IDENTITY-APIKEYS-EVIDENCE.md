# K8.11/K8.2 slice 12: API-key service principals

Related to #70 and the K8.2 track. Owner direction selected long-lived
bearer keys: a service principal is a machine identity owned by one
organization, each key is shown exactly once, only a purpose-bound digest
is stored, rotation overlaps by issue-then-revoke, and disable revokes
every live key.

## Contract

- `internal/auth/apikey.go`: `keel_<secret>` wire form with the public
  prefix as the secret's leading 8 chars (no separator — `_` is valid
  base64url and would make `prefix_secret` ambiguous, caught live by the
  flaky round trip), 128-bit secret floor, `identity-api-key-v1`
  digests (5-purpose separation), bounded service names, optional
  expiry with an hour minimum.
- Migration `0076_identity_api_keys`: forced-RLS
  `identity_service_principals` (single org, disable-once) and
  `identity_api_keys` (prefix, unique digest, optional expiry, revoke
  and use-stamp history) with guards and five `keel_identity`-gated
  functions: owner/admin creates the principal; issue checks a live
  principal and global digest uniqueness; verify reports
  `valid`/`unknown`/`revoked`/`expired` and stamps last use on success;
  revoke is single-shot; disable revokes every live key.
- `internal/auth/postgres`: `CreateServicePrincipal`
  (`not_authorized`→`ErrNotAuthorized`), `IssueAPIKey` (returns the
  wire form once; `unknown_principal`→`ErrNotFound`,
  `key_reuse`→`ErrTokenReuse`), `VerifyAPIKey` (transparent outcomes),
  `RevokeAPIKey`/`DisableServicePrincipal` (`unknown`→`ErrNotFound`).

## Verified

- `go vet ./internal/auth/...` and `gofmt` clean;
  `go test ./internal/auth/...` pass (format round trip incl.
  separator-in-secret, 5-purpose separation, TTL bounds).
- Migration applied live through the runner (`0076` ledgered).
- In-container against real capability roles:
  `--- PASS: TestPostgreSQLIdentityAPIKeys` — owner/admin creation
  vs stranger refusal, issue-then-verify resolving the full identity,
  tampered-key `unknown`, rotation overlap with predecessor valid,
  revoke with repeat converging and post-revoke `revoked`, backdated
  `expired`, disable revoking live keys with repeat converging, FORCE
  RLS with no grants to any non-owner across all thirteen tables, and
  cross-role denials.
- All six earlier suites pass in the same run, twice consecutively.

## Limits

- No HTTP surface for principals/keys yet; verification is a repository
  call, not middleware.
- No key listing, naming, metadata, per-key scopes, usage metering or
  audit trail; no automatic expiry rotation.
- Prefixes are first-8-chars convention only, not guaranteed unique.

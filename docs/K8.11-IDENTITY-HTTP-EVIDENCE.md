# K8.11 slice 3: unmounted identity HTTP surface with file pepper

Related to #70 (K8.11 partial; does not close it). Storage slices 1-2 made
sign-in and recovery possible; this slice makes them reachable: six
unmounted JSON routes with the same hardening shape as the webhook
operator surface. No route is mounted and no production identity,
rate limiting, or email transport is wired.

## Contract

- `internal/auth/pepper.go`: `ReadPepperFile` loads the deploy-time pepper
  from a secret file (never committed), mirroring the OnCall `url_file`
  pattern. Empty path, missing file, `<32-byte` material and `>1024-byte`
  material all fail closed. Runtime mounting (compose secret + role
  wiring) stays open; tests pass a fixed in-process pepper.
- `internal/auth/httpapi` (unmounted `Handler`, `New` validates repo,
  senders, `>=32-byte` pepper and bounded Argon2 params):
  - `POST /v1/auth/principals` `{email,password}` validates canonical
    email and password bounds, hashes (injected effort: production
    `DefaultArgonParams`, tests `TestArgonParams`), bootstraps with nil
    tenant, records a 24 h verification and delivers the token only via
    `VerificationSender`; responds `201 {principal_id,state}` without
    the token. `409 email_conflict` on duplicate; `400` on bad input.
  - `POST /v1/auth/verifications/consume` `{token}` maps
    `verified→200`, `duplicate→409`, `expired→410`, `unknown→404`.
  - `POST /v1/auth/sessions` `{email,password}` never enumerates:
    unknown email, non-active principal and wrong password all return
    `401 invalid_credentials`; corrupt stored hash is `500`. Success
    mints a 24 h session and returns it once:
    `201 {session_id,token,expires_at}`.
  - `POST /v1/auth/sessions/revoke` (`Authorization: Bearer`) revokes
    by resolved session id; unknown/missing token is `401`, repeat
    revoke converges on `204`.
  - `POST /v1/auth/password-resets` `{email}` never enumerates: every
    well-formed address gets `202`, sending only for a recorded active
    principal; malformed input is `400`.
  - `POST /v1/auth/password-resets/rotate` `{token,new_password}`
    validates the new password, re-hashes and maps
    `rotated→200 {principal_id}`, `duplicate→409`, `expired→410`,
    `unknown→404`, `principal_inactive→403`.
  - Bounded `8 KiB` bodies, `DisallowUnknownFields`, single-JSON-value
    rule, `problem+json` errors with fixed codes, `no-store`/`nosniff`/
    `no-referrer`/deny-frame headers. No email, digest, hash or token
    is logged; responses carry only the IDs/tokens the caller must see.
- `Makefile local-identity-test` now compiles and runs both the store
  suite and the HTTP wiring suite inside the PostgreSQL container.

## Verified

- `go vet ./internal/auth/...` clean; `gofmt` clean on touched files.
- `go test ./internal/auth/...` pass: pepper file tests, purpose
  separation, hash lifecycle, session bounds, plus 9 handler unit
  groups (register + conflict + bad input, verify outcomes, login
  convergence, logout idempotence, reset anti-enumeration, rotate
  outcomes, constructor rejection).
- Live wiring in-container against real capability roles:
  `--- PASS: TestHTTPIdentityLifecycleAgainstPostgres` — register over
  HTTP (201 + captured verification token, token absent from body),
  verify consume 200, login 201, logout 204, reset 202 with capture,
  rotate 200, old-password login 401, new-password login 201.
- Existing store suites still pass in-container
  (`TestPostgreSQLIdentityBootstrapAndSessionLifecycle`,
  `TestPostgreSQLIdentityRecoveryAndRotation`).

## Limits

- No route is mounted; no runtime composes pepper file, rate limiting,
  trusted login throttling, email delivery, or production identity.
- Sessions default to 24 h; refresh/sliding expiry undecided.
- No lockout counters, no MFA, no audit trail, no OpenAPI entries for
  these unmounted routes, no tenant binding (K8.1/K8.2).

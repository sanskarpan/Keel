# K6.3 slice: content-free worker pass logging

Issue #404 (parent #48, checklist item K6.3). PR #405 merged as
`4c5b9ab79352c19e413b35285ea8d4f12c12b9c0`; contract CI #653 passed on reviewed head
`fc08b32f1080d58ada54c10979ebe0eff28f2e13`. This slice adds a fixed-field aggregate log line per
scheduler pass and suppresses empty idle passes.

## Contract

`scheduler.PassReporter` receives the aggregate `Report` and a failure boolean after each `RunOnce`.
`WithReporter` is optional and rejects nil. The worker runtime passes a JSON logger and emits only:

- `tenants`
- `leased`
- `delivered`
- `retry_scheduled`
- `exhausted`
- `failed`
- `deferred`
- `skipped`
- `tenant_batch_failures`
- `recon_scanned`
- `recon_gaps`
- `recon_missing`
- `recon_failures`
- `pass_failed`

It never logs tenant/endpoint/event/delivery IDs, URLs, payloads, signatures, keys, receiver
responses or raw error text. Discovery, tenant and reconciliation errors are represented only
by the failure boolean/counts. A pass with no tenants, work, outcomes, failures or scan counts
is not logged.

## Verification

- Scheduler tests assert the reporter receives the aggregate tenant count on a pass.
- Runtime tests assert the JSON line contains the fixed fields, contains no tenant/endpoint/delivery
  ID, URL or error field, and emits nothing for an idle pass.
- Existing worker/scheduler suites continue to pass.

## Limits

No log shipping, sampling, retention, redaction pipeline, alerting, paging or production logging
qualification is included. Logs are operational aggregates, not audit records; the database audit
tables remain authoritative.

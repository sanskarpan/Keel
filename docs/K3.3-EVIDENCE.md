# K3.3 vector retrieval evidence

## Delivered scope

PR [#126](https://github.com/sanskarpan/Keel/pull/126) closes issue [#26](https://github.com/sanskarpan/Keel/issues/26). Migration `0015_retrieval_vector_publication` adds immutable model manifests, tenant/cohort-scoped source-generation-bound vector builds and heads, guarded vector rows, and model-specific halfvec HNSW provisioning. The vector repository stages bounded batches, validates immutable model identity and model-input token bounds, finalizes only a complete source snapshot, and publishes through an expected-generation atomic head switch. A vector build is unusable if its lexical corpus generation is no longer current.

Exact cosine search has deterministic chunk-ID tie-breaking and a hard eligible-candidate budget. Optional HNSW search uses model-revision-specific partial indexes, strict iterative scans with bounded scan settings, and exact float32 reranking for returned ANN candidates. An underfilled scan falls back to exact search only when the full build is within the configured fallback budget; otherwise it returns fewer candidates and marks the result degraded. Exact fallback also marks a result degraded if the whole source corpus has fewer candidates than requested.

## Boundaries and operations

This phase provides vector storage, exact/approximate ranking primitives, and publication mechanics. It does not ship an embedding provider, inference or customer-serving API, fusion/reranking, semantic-quality evaluation, recall/latency/capacity qualification, or an erasure/ACL lifecycle. The model fixture is synthetic and must not be used for tenant data. The pgvector extension must be installed by privileged database bootstrap before application migrations; the restricted schema migration role cannot install extensions. HNSW provisioning uses a blocking transactional index build and is not an online migration procedure for populated customer data. Do not enable a real model or customer index until provider quality, workload capacity, online index rollout, retention, encryption, and erasure procedures have been qualified.

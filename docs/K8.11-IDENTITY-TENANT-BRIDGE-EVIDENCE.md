# K8.11/K8.1 slice 14: tenant resolution bridge for sessions

Related to #70 and the K8.1 track. Sessions already carry the active org;
this slice is the single point where a verified bearer session becomes the
tenant context that trusted service code passes to
`tenancy.WithTenantTx`. Identity itself stays pre-tenant.

## Contract

- `internal/auth/httpapi/tenancy.go`: `TenantForRequest` resolves the
  bearer session, requires validity, requires a switched active org,
  and parses it as a `tenancy.TenantID`. Missing/invalid/revoked/
  expired/unswitched/malformed sessions all fail closed with no
  tenant — never a default.
- No migration: the `org_id` column from `0073` is the source of truth.

## Verified

- `go vet ./internal/auth/...` and `gofmt` clean;
  `go test ./internal/auth/...` pass, including the new matrix
  (active-with-org resolves; no-org, revoked, expired, unknown and
  bearerless requests all refuse).
- In-container against the real store:
  `--- PASS: TestHTTPTenantResolutionAgainstPostgres` — register/
  verify/login, unswitched session resolves to nothing, create org,
  switch, resolves to exactly the org id, bad token refuses.

## Limits

- The bridge is a helper, not mounted middleware; no route consumes it
  yet and no `WithTenantTx` call site exists — K8.1 runtime wiring is
  explicitly next.
- Single active org per session; switching is the only change path.

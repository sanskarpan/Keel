# K6.3 slice: webhook worker alert rules and dashboard contract

Issue #397 (parent #48, checklist item K6.3). PR #398 merged as
`2fa411e12bdd46a048b7e2c916d320c884d77449`; contract CI #643 passed on reviewed head
`a04e19d9dfad155f435f223260900eac2cc2b4fd`. This slice adds source-controlled local Prometheus
rules for the content-free webhook worker metrics, the local scrape job and a documented dashboard
query contract.

## Rules

`deploy/monitoring/prometheus/keel-webhook-worker-alerts.yaml` contains eight rules:

- target down;
- stale tenant discovery;
- discovery errors;
- tenant-batch errors;
- due-delivery backlog;
- oldest-due age;
- retry exhaustion;
- due work with no started attempts.

All expressions use only the existing fixed series/outcome labels. No tenant, endpoint, event,
delivery, URL, payload or error string is added.

## Local wiring

`deploy/monitoring/prometheus/keel-local-prometheus.yaml` now loads the worker rule file and scrapes
`127.0.0.1:18082` as `keel-webhook-worker`. `deploy/compose/compose.yaml` mounts the rule file into
the optional local Prometheus profile. `make local-webhook-worker` starts the worker and
`make local-monitoring-up` starts the profile on Linux Docker Engine.

`docs/K6.3-WEBHOOK-ALERTS.md` documents alert meanings, local usage and the dashboard PromQL panels
for target health, backlog, discovery, attempts and outcomes.

## Validation

- `promtool check rules` on the webhook and existing rate-limit rule files: 8 and 4 rules pass.
- `promtool check config` on a rendered local config with the rule paths: valid, both rule files
  found.
- `docker compose --profile monitoring config --quiet`: valid.

The local profile was not run against a live receiver; the worker egress policy rejects loopback and
private destinations. This validates rule/config syntax and the source-controlled contract, not
deployed alert delivery.

## Limits

No Alertmanager, notification delivery, paging ownership, Grafana JSON, hosted dashboard, SLO
burn-rate qualification or production deployment is included. Thresholds are local starting points
and require review against traffic and the selected monitoring stack.

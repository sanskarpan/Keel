# K6.3 slice: delivery worker loop

Issue #359 (parent #48, checklist item K6.3). PR #362 merged as
`032a95ec0995c194a512ea44e2fc9e8753c33962`; contract CI #596 passed on reviewed head
`6a470f7730342e4e17019920a53435df21803ce1`. This slice composes the earlier K6.3 pieces into one single-tenant
loop: lease a due batch, admit the endpoint breaker, resolve the endpoint revision, fetch the exact
payload, execute one signed attempt, record the fenced outcome, schedule the next retry and observe
the outcome into the persisted breaker.

## Loop

`worker.Runner.Run(ctx, tenant, batch)` leases 1-100 due deliveries for one trusted tenant with a
5-300 second fence (60 seconds by default) and processes them in lease order.

For each lease:

1. Load the endpoint's persisted breaker; a missing row is a closed breaker at version zero.
2. Run `BreakerPolicy.Allow` at the loop clock.
3. If admission changes the state (an elapsed cooldown moves `open` to `half_open`, or a probe is
   admitted), save it with the loaded version before any request. A version conflict or save error
   skips the lease without sending.
4. If admission is denied, record a retryable attempt with HTTP status 0, zero latency and a next
   time after the cooldown (or at least five seconds for a saturated half-open probe slot). The
   scheduler still applies the attempt ceiling and retry window.
5. Resolve the active endpoint at the delivery's subscription revision. `ErrEndpointUnavailable` is
   recorded as permanent; other store errors skip the lease.
6. Fetch the exact payload through the injected `PayloadSource`. Empty, oversized or
   `ErrInvalidDelivery` payloads are permanent; other source errors are retryable.
7. Send one attempt through the injected `Sender` (the K6.3 executor in production). A returned
   sender error is a data/config error: nothing is recorded and the lease expires.
8. Record the outcome under the lease epoch and attempt number. Retryable outcomes get the
   scheduler's full-jitter next time, or no time when the ceiling/window is exhausted.
9. Recompute the breaker from the post-admission state and the outcome. Delivered and permanent
   close it; retryable increments failures or reopens a failed probe with the doubled cooldown. Save
   only when the state changed, using the latest version. A conflict after recording is reported but
   does not undo the attempt.

A per-delivery error does not abort the rest of the batch; errors are joined. Processing stops early
only when the context ends.

## Lease window

Migration `0045` re-creates `lease_webhook_deliveries` (drop and create, because the return type
changes) with the delivery's `first_attempt_at`. `postgres.Lease` carries `FirstAttemptAt` and
rejects a zero value or one after the fence expiry. The worker passes it to the scheduler, so the
24-hour retry window is enforced from the delivery's first lease rather than from the current
attempt. The function keeps the same capability gate, due/expired selection, `SKIP LOCKED` locking,
monotonic epoch and 5-300 second bound; only the returned column set changes.

## Breaker deferral semantics

A denied attempt has no HTTP exchange, but the lease already consumed an attempt slot. The loop
records it as `retryable` with status 0 so the ledger remains consistent with the attempt counter
and the deferral is visible. This deliberately spends attempt budget while an endpoint is down;
a delivery that stays behind an open breaker can therefore reach exhaustion. A later slice could
add an explicit deferred lease transition that does not count an attempt (the current state guard
makes attempt counters monotonic, so this cannot be done by releasing the lease).

A half-open probe state is saved before sending by design: another worker sees the probe as taken,
so only the configured number of probes can be in flight. If the process dies after saving the probe
but before recording, the breaker remains half-open with the probe counted until an operator or a
later slice reconciles it.

## Coverage

Unit tests use fakes for the store, payload source and sender, plus the real retry scheduler and
breaker policy with a fixed clock. They cover delivered-from-closed, retryable opening the breaker,
permanent closing a breaker with prior failures, open-breaker deferral without sending, half-open
probe admission saved before the send (including call order), a saturated half-open probe slot,
endpoint unavailability, invalid and unavailable payloads, a pre-send breaker save conflict,
exhaustion with no next time, per-delivery failure isolation, input/tenant/batch bounds and an
invalid lease. PostgreSQL coverage asserts the lease now returns `first_attempt_at` and the existing
lease/record/fencing/breaker suites continue to pass.

## What is still missing

This slice adds no production payload retrieval (provided separately by #364, see
`docs/K6.3-PAYLOAD-SOURCE-EVIDENCE.md`), tenant scheduling or quotas, worker process wiring,
metrics, operator replay execution or UI. Tenant scheduling and process wiring are provided
separately by #372 (`docs/K6.3-WORKER-RUNTIME-EVIDENCE.md`); quotas, metrics and replay execution
remain open. The loop does not log: delivery IDs may be safe, but endpoint URLs and transport errors
must never reach logs, so observability waits for a content-free metric/log contract. Replay
authorization is provided separately by #365; replay execution remains open.

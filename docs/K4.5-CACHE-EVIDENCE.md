# K4.5 cache eligibility and qualification evidence

## Delivered scope

Issue #192 adds a content-free policy boundary for future cache adapters. `internal/ai/cache` does not embed prompts, search vectors, store responses, or claim a live cache hit. It gives an adapter a canonical scope digest, an opaque HMAC lookup key, a fail-closed eligibility predicate, and a per-serving-policy evaluation gate.

Every scope binds tenant, current access decision, policy, prompt, provider and model versions, tool policy, context and source-set versions, locale, classification, and cache-policy version. Changing any bound value changes the scope digest and forces a miss. Only `general` classification is eligible. HMAC key material is injected, must be at least 256 bits, and is domain-separated. The key ID is included in the lookup key so rotation invalidates old entries. The caller's canonical prompt bytes are used only to derive the HMAC; the package has no logging or persistence API.

An exact candidate must match the current opaque key and scope, remain unrevoked and within its bounded lifetime, and be under the active cache kill switch. A semantic candidate additionally requires a different exact key, the same pinned verifier ID/version/artifact digest and threshold, a passing similarity score, and equal server-derived entity, numeric, date, and polarity evidence digests. Missing evidence or verifier metadata is a miss. This contract does not make an untrusted query parser or verifier trustworthy; those implementations require separate review and artifact pinning.

## Precision qualification

`Assess` consumes content-free curator export rows for exactly one serving policy. It requires unique pair IDs, unique independence-unit IDs among served pairs, an adjudication reference for every row, and an explicit independent-label attestation for every served pair. It calculates the one-sided 95% exact Clopper-Pearson lower confidence bound. Qualification requires at least 600 independent served pairs and a lower bound of at least 99.5%. With zero false hits among 600, the lower bound is approximately 99.5019%. Tenant/permission leakage and entity, numeric, date, or polarity mismatches fail qualification regardless of the aggregate bound. Missed opportunities are reported separately from precision.

The package validates curator attestations and independence identifiers; it cannot establish that human adjudication was blinded, labels are correct, or observations are statistically independent. That evidence must come from the separately governed corpus and review process. No K4.5 corpus or production serving policy has been evaluated in this change, so there is no measured quality claim and semantic serving remains disabled.

## Security and operations

- Load current authorization, context/source generations, policy digests, verifier identity, and server-derived risk facts before eligibility evaluation.
- Fetch the response only after eligibility succeeds, through a tenant-scoped encrypted store. This package never handles response bytes.
- Invalidate entries when access, source, policy, prompt, tool, model, or cache-policy versions change. A stale scope must miss even if asynchronous deletion has not completed.
- Keep cache disabled for sensitive or unclassified inputs and preserve an immediate global/per-scope kill switch.
- Do not treat cache savings as provider spend reduction until the serving path measures verifier, embedding, storage, and retrieval costs.

## Verification and remaining gates

The package tests cover key opacity and scope binding, key rotation, sensitive-input refusal, authorization changes, expiry/revocation/kill switch, verifier pinning, entity/numeric/date/polarity mismatches, duplicate/dependent/mixed-policy labels, the 599/600 boundary, exact confidence bounds, and risk failures that aggregate precision cannot excuse. Local Go 1.27.1 `go test ./...`, `go vet ./...`, and `go test -race ./internal/ai/cache` pass.

Still required under parent issue #35: a reviewed similarity/verifier implementation, independently adjudicated eligible-hit corpus per actual serving policy, zero privacy/risk-fact false hits, measured >=99.5% one-sided lower bound, encrypted persistent storage and retention/erasure behavior, live authorization revocation tests, load/cost qualification, and a tested rollout/rollback kill switch. This change is policy and qualification infrastructure only.

# K6.3 slice: active webhook endpoint quota

Issue #391 (parent #48, checklist item K6.3). This slice bounds new active-endpoint growth at 100
per tenant, serializing registration and status changes so concurrent requests cannot exceed the
cap.

## Contract

Migration `0054_webhook_endpoint_quota` re-creates `register_webhook_endpoint` and
`set_webhook_endpoint_status` with a per-tenant transaction advisory lock and an active-endpoint
count check:

- Creating an endpoint when the tenant already has at least 100 active endpoints fails with
  `webhook active endpoint quota exceeded`.
- Reactivating an inactive endpoint when the tenant already has 100 active endpoints fails the same
  way.
- Updating an existing endpoint, deactivating, and re-applying `active` to an already-active
  endpoint remain allowed.
- The check and mutation run under the same per-tenant lock, so two concurrent creations at 99
  active endpoints produce one success and one quota rejection.
- The cap is per tenant; another tenant is unaffected.
- Existing over-cap tenants are not rewritten, deactivated or deleted. The cap protects new growth
  only.

`webhook.MaxActiveEndpointsPerTenant` documents the initial limit. `postgres.Registry.Register` and
`SetStatus` map the database rejection to `webhook.ErrEndpointQuota`.

## Verification

Coverage runs against a fresh PostgreSQL database with migrations through `0054`:

- 100 active endpoints can be created; the 101st and a reactivation at the cap fail with
  `ErrEndpointQuota`;
- updating an endpoint at the cap succeeds;
- deactivation frees a slot and creation or reactivation then succeeds;
- two concurrent creations at 99 active endpoints produce exactly one success and one quota
  rejection;
- another tenant can still register.

## Limits

This is an initial fixed cap, not a configurable tenant policy or operator override. It does not
quota due deliveries, attempts, payload size or fanout latency, and it does not retroactively
remediate existing over-cap data. There is no HTTP/UI, billing limit or hosted quota qualification.

# K7.1 slice: Supabase staging + Modal deployment

Related to #52 (K7.1 partial; does not close it). This slice stands up the designated
Supabase staging database and deploys the operator API and webhook worker to Modal, with
every managed-platform difference found and fixed along the way. No production
qualification is claimed.

## What runs

- **Staging database** (Supabase Postgres 17.11, pgvector 0.8.2): role bootstrap applied,
  all 62 migrations applied through the staging migrator login, 93 `keel_meta` tables and
  129 functions.
- **Modal app `keel`** (deployed): `serve_operator_api` (web endpoint, bearer auth, health),
  `run_webhook_worker` (persistent loop, `min_containers=1`), `migrate_db` (one-shot).
- **Verified live** against staging: `/health/ready` → 200, `/version` → 200,
  `GET /v1/webhooks/reconciliation-runs` → 200 with no auth header → 401, bad token → 401,
  `limit=0` → 400, and `GET /ui` → 200 with the rendered dashboard.

## Managed-platform findings (each cost a failed attempt)

1. **Modal functions need Python in the image.** A `golang:*` base fails with "unable to
   determine the version of Python installed". The image is now `debian_slim` + the Go
   toolchain downloaded and checksum-verified from the pinned baseline version.
2. **`add_local_dir` must use `copy=True`** when a build step follows it; otherwise Modal
   rejects the image with a build-ordering error.
3. **`os.execv` breaks the web tunnel.** Replacing the Python process removes Modal's port
   supervisor, so the endpoint times out and the container recycles. The server now runs as
   a child process and the function returns; startup is idempotent (port probe) because the
   function can run more than once per container.
4. **pgx prepared-statement cache breaks behind a transaction-mode pooler.** The operator
   API returned intermittent then consistent 500s with
   `prepared statement "stmtcache_..." already exists`; staging DSNs now set
   `default_query_exec_mode=exec`.
5. **Supabase pooler needs the project ref in the username** (`role.<project-ref>`,
   otherwise `ENOIDENTIFIER`), **session-mode pooling (5432)** for migrations/`SET ROLE`/
   advisory locks, and its **private CA pinned** for `sslmode=verify-full`
   (`deploy/modal/supabase-ca-2021.pem`, public trust material).

## Contract

- `deploy/modal/keel.py` builds from source with the pinned Go toolchain, pins the Supabase
  CA, and excludes `.git`, `.env`, caches and non-build docs from the image context.
- `deploy/modal/staging-roles.sql.template` bootstraps the managed database without
  local-synthetic logins; staging passwords are substituted at apply time and never
  committed.
- Secrets hold verify-full DSNs with the pinned CA path and `default_query_exec_mode=exec`.

## Limits

Single staging environment; no production region, backup/PITR, failover, capacity or
monitoring qualification; Kafka/Redis/Temporal-backed roles are not deployed; the worker
currently has no real receiver (egress policy rejects loopback/private targets). Credentials
live only in the gitignored `.env` and Modal secrets.

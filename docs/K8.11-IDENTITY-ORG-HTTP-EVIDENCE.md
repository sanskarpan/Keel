# K8.11/K8.1 slice 8: organization HTTP surface

Related to #70 and the K8.1 onboarding track. Storage proved first
binding; this slice serves it: three unmounted routes with the session
principal as the only actor. No route is mounted.

## Contract

- `internal/auth/httpapi/organizations.go` (same hardening as the
  identity surface: `8 KiB` bodies, `DisallowUnknownFields`,
  `problem+json` fixed codes, security headers, no email/token logging):
  - `POST /v1/auth/organizations` `{slug,display_name,region}`
    validates bounds in Go, creates with the session principal:
    `201 {org_id,slug,display_name,region,role:owner}`,
    `409 already_bound` for bound founders, `409 slug_conflict`,
    `403` for a raced deactivation, `400` for bad input,
    `401` without a session.
  - `POST /v1/auth/organizations/{org_id}/members` `{email,role}`
    names the member by email (canonical validation, admin/member
    only — owner grants are rejected at the edge with `400`):
    unknown addresses `404 not_found`, inactive members
    `422 member_inactive`, then `201 {org_id,principal_id,role}`,
    `403` for non-owner/admin actors, `409 already_member`,
    `409 tenant_conflict` for cross-org principals.
  - `GET /v1/auth/organizations` returns the caller's orgs with roles;
    empty is `200` with an empty list, never 404.
- The `httpapi.Repository` interface grows the three organization
  calls; `*postgres.Repository` already satisfies it.

## Verified

- `go vet ./internal/auth/...` and `gofmt` clean;
  `go test ./internal/auth/...` pass, including new mapping groups
  (create outcomes + bad input + missing bearer, member outcomes +
  role/email/org-id rejection, list populated/empty).
- In-container against real capability roles:
  `--- PASS: TestHTTPOrganizationLifecycleAgainstPostgres` — register/
  verify/login helpers drive owner create `201` with owner role, owner
  list contains the org, second foundation `409`, member add `201`
  with member-visible listing, member seating `403`, unknown address
  `404`, owner grant `400`, re-add `409`.
- Earlier HTTP and store suites pass in the same runs.

## Limits

- No routes mounted; no runtime wiring.
- Members are named by email only; no principal-id or invite-token
  addressing yet (invite flow is the explicit next K8.2 slice).
- No pagination on the org list (bounded by one-membership-per-principal
  for now), no transfer/demotion/removal, no audit trail.

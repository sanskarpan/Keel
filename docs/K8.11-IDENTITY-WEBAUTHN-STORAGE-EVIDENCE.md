# K8.11 slice 5: WebAuthn credential and challenge storage (MFA foundation)

Related to #70 (K8.11 partial; does not close it). Owner direction selected
WebAuthn first for MFA; this slice is the durable foundation: ceremony
challenges with a 10-minute window, credential public-key storage bound to
a consumed registration challenge, and monotonic sign counts with clone
reporting. Attestation/assertion cryptography and the HTTP ceremony
endpoints arrive in the next slice; this one proves the state machine.

## Contract

- `internal/auth/webauthn.go`: registration/authentication purposes
  (`identity-webauthn-registration-v1` /
  `identity-webauthn-authentication-v1`), 32-byte nonces, 1–10 minute
  challenge window, credential-ID (1–1024) and COSE-key (1–2048) bounds,
  allowlisted transports (`usb,nfc,ble,hybrid,internal`, max 5), and
  `CheckSignCount`: counterless pairs carry no signal, strictly
  increasing advances, anything else is `cloned` and must fail closed.
- Migration `0069_identity_webauthn_credentials`: forced-RLS
  `identity_webauthn_credentials` (unique credential id, active-principal
  FK, key bytes, `sign_count`, transports, backup-eligible/state, use
  shape) and `identity_webauthn_challenges` (unique id, principal FK,
  purpose check, unique 32-byte nonce, window/shape checks) with guard
  triggers; six `keel_identity`-gated SECURITY DEFINER functions:
  `record_identity_webauthn_challenge` (active-only, 10-minute SQL
  ceiling, global nonce `challenge_reuse`, resend replacing the pending
  row), `consume_identity_webauthn_challenge`
  (`ready`/`unknown`/`duplicate`/`expired` with principal, purpose and
  nonce), `register_identity_webauthn_credential` (atomic consume of a
  registration challenge, active check, `credential_reuse`,
  `wrong_purpose`), `identity_webauthn_keys_for` (key set for assertion
  verification), `advance_identity_webauthn_sign_count` (`advanced`,
  `cloned` without applying, `unknown`). Migration `0070` forward-repairs
  the `purpose` variable/column ambiguity that aborted consume and
  register with SQLSTATE 42702.
- `internal/auth/postgres`: `RecordWebAuthnChallenge` (`not_active` to
  `ErrNotVerified`, `challenge_reuse` to `ErrTokenReuse`),
  `ConsumeWebAuthnChallenge` (transparent outcomes + nonce),
  `RegisterWebAuthnCredential` (transparent outcomes),
  `KeysFor` (empty when unenrolled, range-checked counters),
  `AdvanceSignCount` (transparent outcomes).

## Verified

- `go vet ./internal/auth/...` and `gofmt` clean;
  `go test ./internal/auth/...` pass (challenge bounds, credential
  bounds, all five sign-count cases).
- Migrations applied live through the runner (`0069`, `0070`
  ledgered).
- In-container against real capability roles, three consecutive full
  runs: `TestPostgreSQLIdentityWebAuthn` **PASS** — pending-principal
  refusal, under-min TTL rejection, resend replacement with the
  replaced id resolving `unknown`, single-use `ready` with purpose and
  nonce equality, `duplicate`, cross-principal nonce `challenge_reuse`,
  atomic `registered` with key-set equality, spent-challenge
  `duplicate`, `wrong_purpose`, cross-principal `credential_reuse`,
  empty key set for the other principal, `advanced` 0→1→41, `cloned`
  on replay and regression, `unknown` advance, backdated `expired`
  consume, FORCE RLS on both tables with no grants to any non-owner
  across all eight tables, and `keel_local_app` / `keel_local_identity`
  denials. Two live-caught bugs fixed pre-commit: the SQL ambiguity
  (forward repair `0070`) and deterministic test nonces/credential id
  colliding with prior runs (fresh randomness per run).
- Earlier suites still pass in the same runs (bootstrap, recovery,
  lockout).

## Limits

- No ceremony cryptography: attestation verification, assertion
  signature checks and the `go-webauthn` ceremony integration are the
  explicit next slice; no HTTP endpoints yet.
- No credential deletion, rename, per-credential policy, backup-state
  enforcement, or admin revocation: still open under #70.
- Transports are a validated comma list, not a normalized table; a
  later slice may normalize if querying demands it.

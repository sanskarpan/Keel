# K6.3 slice: persisted per-endpoint breaker state

Issue #353 (parent #48, checklist item K6.3). PR #354 merged as `69b21a0bb9c35bdede4335e82e9e096670bce147`; contract CI #583 passed on reviewed head `b95ec73704e1598a4ae60a03d993bc1ac4818c95`. This slice turns the pure breaker policy into
shared state: every delivery worker loads one endpoint's breaker, applies the policy, and saves the
result under an optimistic version. It does not consult the breaker during leasing, run a worker or
expose an operator reset.

## State

Migration `0043_webhook_endpoint_breakers` adds `keel_meta.webhook_endpoint_breakers`, keyed by
`(tenant_id, endpoint_id)` with a foreign key to the endpoint registry:

| Column | Contract |
| --- | --- |
| `status` | `closed`, `open` or `half_open` |
| `failures` | consecutive retryable failures while closed; zero while open or half-open |
| `opened_at`, `open_for_seconds` | cooldown start and length, null only while closed |
| `probes` | admitted half-open probes |
| `version` | starts at 1, increases by exactly one per save |
| `updated_at` | database clock |

Check constraints enforce the state shape: closed has no cooldown, open has no failures or probes,
half-open has no failures, cooldowns are 1 second-24 hours and probes are bounded at 10. Forced RLS,
revoked direct grants and a guard trigger refuse deletes and identity changes; the version must
increase by one.

## Shared state, not shared policy

The policy stays in Go (`BreakerPolicy.Allow` and `Observe`); PostgreSQL owns the row and the
compare-and-swap, not the decision. A worker loads the state, computes the next state with its policy
and clock, and saves with the observed version. A concurrent save at the same version loses with a
version conflict; it reloads and recomputes instead of overwriting the winner. This keeps one policy
implementation and lets a later slice tune the policy without a migration.

A missing row is the zero, closed breaker at version zero, so a new endpoint needs no initialization.
The first save inserts; subsequent saves use the exact-match update. Detecting a cooldown transition
is therefore also a write: `Allow` may return a changed half-open state while denying or admitting,
and the caller persists whatever it computed.

## Access

Both `load_webhook_breaker` and `save_webhook_breaker` are security-definer functions gated on
membership in `keel_webhook` and derive the tenant from the authorized transaction context, the same
boundary as delivery leasing and attempt recording. `keel_app` cannot read or write breaker state,
and no runtime role has direct table access. The row stores no URL, key or content, so it is safe to
aggregate but is still tenant-scoped.

## Validation

The Go store normalizes an empty status to closed, then checks the structural invariants and the
bounds the database repeats: failures 0-1,000,000, probes 0-10 and a 1 second-24 hour cooldown for
non-closed states. An out-of-range or inconsistent state is rejected before any statement runs. A
loaded row is validated again before it reaches the policy, so a corrupted row fails closed instead
of being silently normalized.

## Coverage

Unit tests cover invalid contexts, tenants and endpoint IDs, negative and oversized expected
versions, and every invalid state shape or bound. PostgreSQL integration tests cover the missing-row
zero state, insert, stale insert, open and half-open transitions, close/reopen, timestamp round trip
and `OpenUntil`, unknown-endpoint foreign-key rejection, two concurrent saves at one version
producing one winner, direct table access denial for both runtime roles, app-role function denial and
delete rejection.

## Boundaries

No leasing-time breaker lookup, attempt execution, endpoint-scoped metric, operator reset, manual
close or alert. The breaker is not yet connected to a delivery worker; the existing retry scheduler
leases work without consulting it. Delivery-side enforcement is a later K6.3 slice.

# K6.5 slice: adversarial webhook and callback qualification

Issue #388 (parent #50, checklist item K6.5). This slice adds qualification tests for receiver
failure/recovery, replay after key rotation and replay after a DNS answer changes to a private
address, and records the callback and worker coverage already present.

## Qualification matrix

| Scenario | Evidence | Result |
| --- | --- | --- |
| Exact callback redelivery after apply | `TestPostgreSQLCallbackInboxAppliesExactlyOnce`, `TestPostgreSQLCallbackInboxAppliesConcurrentDeliveryOnce` | Duplicate receipt; no second effect |
| Same callback ID with different payload or another tenant | `TestPostgreSQLCallbackInboxRejectsPayloadConflict`, `TestPostgreSQLCallbackInboxRejectsCrossTenantReplay` | Conflict; no effect; no other-tenant disclosure |
| Authentic callback whose application fails | `TestPostgreSQLCallbackInboxRollsBackFailedApplication` | Inbox record rolls back so a later retry can apply |
| Receiver returns 5xx then recovers | `TestQualificationReceiverFailureThenRecovery` | First attempt retryable; second delivered; two receiver requests |
| Retry/exhaustion/breaker/fenced lease | Existing `worker` and `postgres` retry, breaker, lease and worker suites | Durable retry, exhaustion, deferral and stale-lease fencing |
| Replay after signing-key rotation | `TestQualificationReplayAfterKeyRotationFailsClosed` | Old key is rejected before send; old delivery revision under a new endpoint revision is rejected before send |
| Replay after DNS answers change to a private address | `TestQualificationReplayAfterDNSChangeFailsClosed` | Re-evaluated dial denies the private answer; outcome permanent; no second request |
| DNS re-resolution, mixed answers and pinned address | Existing K6.2 egress suite | Fails closed on any non-public answer; pins the vetted address |

## New tests

`internal/delivery/webhook/qualification_test.go`:

- `TestQualificationReceiverFailureThenRecovery` sends one signed attempt to a TLS receiver that
  returns 503, then a second attempt that returns 204. The executor classifies retryable then
  delivered and the receiver sees exactly two requests.
- `TestQualificationReplayAfterKeyRotationFailsClosed` first delivers with `key_2026`, then builds a
  keyring with only `key_2027`. Reusing the old endpoint key fails with `ErrInvalidKeyring`; moving
  the endpoint to revision 2 while keeping the old delivery revision fails with `ErrInvalidEndpoint`.
  The receiver count stays at one, so a rejected replay never sends.
- `TestQualificationReplayAfterDNSChangeFailsClosed` resolves the same host to a public address,
  delivers, closes idle connections, changes the resolver answer to a private address and retries
  the same delivery. The dial is denied, the result is permanent with HTTP status 0 and the
  receiver count stays at one.

## Limits

This is not a provider-adapter or production qualification. There is no real provider callback
adapter, production DNS, deployed receiver, operator replay UI or mounted runtime route. The callback
inbox has no domain-specific late/impossible-state adapter; its rollback test proves the inbox
boundary, not a provider's late-event policy. K6.5 and the K6 gate remain open for end-to-end
provider evidence, replay execution/UI, and production network qualification.

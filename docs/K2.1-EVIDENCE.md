# K2.1 supplier evidence intake implementation evidence

Implementation is tracked by [PR #118](https://github.com/sanskarpan/Keel/pull/118), which closes [issue #17](https://github.com/sanskarpan/Keel/issues/17). The PR contains one commit per changed file.

## Delivered behavior

- Supplier invitations are tenant/case/supplier scoped, single-use and expire within seven days. Invitation and supplier-session bearer secrets are independent 256-bit values; only purpose-separated digests are stored. Recipient email is persisted only as a peppered HMAC digest.
- Upload metadata is validated before admission. The receiver independently enforces the byte limit, media type, file signature and SHA-256 while writing into a private local quarantine store. The allowlist is PDF, DOCX and UTF-8 text; DOCX archive paths, macros and expansion are bounded and checked.
- A short-lived upload capability binds tenant, invitation, upload ID, exact length, digest and purpose. Scanner and extractor adapters use fixed internal endpoints, bounded I/O and fail-closed behavior. Tika redirects and proxy environment settings are disabled.
- PostgreSQL tables use forced tenant RLS. Upload work is claimed by the distinct `keel_file_processor` database role with expiring leases and monotonically increasing fencing epochs. A stale processor cannot publish completion. The app role cannot claim processing jobs.
- Extracted text remains private output; it is bounded, UTF-8 checked and published only after successful scan/extraction and a fenced database completion. Failed completion deletes the newly written output where the process remains alive.

## Operational and rollback limits

The current `LocalStore` is for synthetic/local use only. It uses UUID-only object names, a private directory, restrictive file permissions, atomic create-if-absent writes and bounded deletion, but does not qualify hosted object storage, object version binding, KMS encryption, retention/erasure, or crash-orphan reconciliation. The ClamAV image provides deterministic test signatures; this evidence says nothing about signature freshness or production update ownership.

The HTTP handler package defines authenticated internal invitation issuance and bearer-protected supplier routes, but the Keel API runtime does not yet mount it or provide production OIDC/session resolution. Do not expose the handler directly or accept customer evidence until the K0 identity/runtime gate and K0.1 provider decision are complete. No production or hosted pilot is enabled by this work.

Migration `0008_supplier_evidence_intake` is additive. Rollback of a deployed build should first disable intake at the owning API/runtime release boundary; table removal or quarantined-object deletion requires a separately reviewed retention-safe operation. Process-crash object reconciliation is still open. Operational ownership is the Keel platform team; a named on-call owner has not yet been assigned.

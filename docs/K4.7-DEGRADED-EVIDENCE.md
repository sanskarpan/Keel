# K4.7.2 durable safe-read degradation evidence

This is a partial implementation of [issue #198](https://github.com/sanskarpan/Keel/issues/198), under parent [issue #37](https://github.com/sanskarpan/Keel/issues/37). It builds on the Redis admission authority from #196. It does not qualify production traffic or complete issue #198.

## Implemented contract

- PostgreSQL is the shared authority for fallback admission. No limiter-local counter exists; regional fleet tokens, per-tenant/route tokens, outage state and replay receipts survive API process restart and replica changes.
- Source code owns the degraded route classification; only `safe.read` is currently eligible. A control-plane provisioned enabled fleet policy and tenant/route policy then enforce the approved limits for that route. Missing/disabled policies reject, and SQL rows cannot opt model, write, or unclassified routes into fallback. The coordinator and direct PostgreSQL limiter both enforce the source allowlist. Application roles cannot directly inspect or change policy or bucket tables. The limiter and policy repository also require explicit configuration; the fallback is disabled unless configured.
- Admission supports a fixed one-unit request cost. The coordinator rejects fallback for any request whose Redis policy cost is not exactly one unit, avoiding a cheaper SQL retry for a more expensive request. Fleet and tenant capacity plus refill policies bound request count; richer weighted costs are not implemented.
- The first degraded admission opens one regional window capped at 60 seconds by a database constraint. Once expired, it stays closed until the separately credentialed rate-control observer has observed five consecutive seconds of successful home-region Redis PINGs and records recovery. Pod restart, elapsed time, and Redis flapping do not themselves reset the window.
- A stable request UUID replays the exact stored decision for ten minutes. The receipt binds tenant, region, route, request ID, tenant policy digest, fleet policy digest and outage ID. Reusing a request ID with a changed policy conflicts; changing the active policy generation rejects a stale admission. Cleanup is bounded to 100 expired receipts per call, plus deletion of an expired receipt for the exact key before that key is reused. An exact receipt remains replayable for its ten-minute retention period after the original 60-second admission window expires, provided the bound policy generations are still current; replay returns the original decision and spends no additional tokens. A distinct request ID cannot open or extend an expired window. This defines retry semantics for an already-recorded decision, not continued degraded admission.
- The coordinator only attempts SQL fallback after the primary limiter reports `ErrUnavailable`, while the request context remains live. It first requires the source-owned `safe.read` classification; the direct PostgreSQL limiter repeats this check before database access. Model/write and unclassified routes fail closed even if a SQL policy row is provisioned. If PostgreSQL or policy lookup is unavailable, admission fails closed.
- `DegradedMetrics` exports admission result counters and cumulative duration/count series through the existing structural Prometheus `MetricsExtension`. Its result label is a fixed enum; tenant, route, request, region, and outage IDs are excluded. A health-handler test verifies the output and label bound. No current runtime role constructs this limiter or attaches the extension to a live scrape endpoint.
- Redis and PostgreSQL cannot atomically coordinate an ambiguous Redis timeout. A Redis decision may have consumed capacity even if the caller receives `ErrUnavailable`; fallback can then admit a separately charged request. This additive allowance is bounded by the shared SQL fleet and tenant buckets, but is not strict global exactly-once admission across both systems.

## Security and operational boundaries

Only the reviewed control/observer service may hold the rate-control credential; it must not be shared with API, worker, or operator shells.

# K6.4 slice: endpoint status history

Issue #410 (parent #48, checklist item K6.4). PR #411 merged as
`36a4a2980da1a3b698e08325b3bbcc307c9f8084`; contract CI #661 passed on reviewed head
`3098ddbf61e30897787ea693d80d2d53b780f70a`. This slice records append-only endpoint
status/subscription history on every registry version and exposes an operator-gated
point-in-time query, so a later repair slice can reconstruct whether an endpoint was active at
an event's time instead of only consulting current state.

## Contract

- Migration `0058` adds `webhook_endpoint_status_history` keyed by `(tenant,endpoint,version)`
  with a foreign key to the registry, forced RLS, revoked direct grants and an immutable-history
  trigger. An `AFTER INSERT OR UPDATE` trigger on `webhook_endpoints` records one row per
  version (status, subscription revision, update time); existing endpoints are backfilled at
  their current version. Versions before this migration have no history.
- `keel_operator`-gated `webhook_endpoint_status_at(endpoint,at)` returns the latest recorded
  status, subscription revision, version and record time at or before the query time, or zero
  rows when the endpoint is unknown or was created later. It exposes no URL, key, payload or
  receiver data.
- Go adds `EndpointStatusAtQuery`/`EndpointStatusPoint` with validation and
  `Store.EndpointStatusAt` over the operator capability, mapping no history to
  `ErrEndpointUnavailable` and invalid shapes to `ErrInvalidEndpoint`.

## Limits

Repair still consults current active endpoints; no repair semantics change, scheduler
integration, reconciliation UI/metrics or HTTP exposure. History starts at this migration.

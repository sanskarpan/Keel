# K6.3 slice: replay execution end to end

Issue #419 (parent #48, checklist item K6.3). PR #420 merged as
`5d3f98200fb6c70b9793d1a6bf357272a0a7dbf9`; contract CI #673 passed on reviewed head
`ec7bb6c226d22fde3b5b193913043637437b939f`. This slice proves the full replay execution path
with real stores, payloads and signed HTTP: no production code changes were needed.

## Contract

- `TestReplayExecutionRedeliversThroughWorkerLoop` (DB-gated, in the worker package to avoid a
  store/runner import cycle) wires a real registry, lease/breaker/record store, payload source,
  signed executor against a TLS test receiver, and the operator replay authorizer.
- Leg one fails permanently (receiver 400): one leased failure, state `failed`, one attempt,
  `first_attempt_at` set.
- The operator requeues the delivery (audited, budget preserved: prior attempts 1).
- Leg two redelivers (receiver 204): state `delivered`, attempts 2, `first_attempt_at`
  unchanged, two attempt rows, two receiver requests sharing the delivery ID with fresh attempt
  IDs and test-key signatures.

## Limits

No mounted replay route, production identity, retry/breaker semantics change or HTTP/UI. The
receiver is a test TLS server reached through a test-only egress dial hijack; DNS rebinding and
address vetting are covered by the existing egress tests.

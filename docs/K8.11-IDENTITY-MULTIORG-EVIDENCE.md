# K8.11/K8.1 slice 9: multi-org memberships with per-session active org

Related to #70 and the K8.1 onboarding track. Owner direction selects
several memberships per principal with an explicit active-org switch on
each session; the tenant stays first-bound as the primary. Invites, owner
transfer, service principals and tenant-context wiring stay open.

## Contract

- `internal/auth/session.go`: `Session.OrgID` carries the session's
  active organization (empty when none selected); validity ignores it.
- Migration `0073_identity_multi_org_switch`:
  - drops the single-membership unique constraint;
  - adds `identity_sessions.org_id` (nullable FK);
  - replaces `create_identity_organization` / `add_organization_member`
    so founding and joining never refuse an already-placed principal
    (`already_bound` and `tenant_conflict` outcomes are gone; the
    tenant binds only when NULL);
  - replaces the sessions guard to permit capability-gated org
    transitions while keeping every other field immutable;
  - drops and recreates `identity_session_for` with the `out_org_id`
    column (return-type growth, which CREATE OR REPLACE rejects —
    the failed apply was caught live and fixed pre-commit);
  - adds `switch_identity_session_org` (`switched`, membership-checked;
    revoked, expired and unknown sessions report `unknown_session`).
- `internal/auth/postgres`: `SessionForToken` resolves the active org;
  `SwitchSessionOrg` maps `unknown_session` to `ErrNotFound`;
  `not_member` is a transparent outcome for the caller to judge.
  The `httpapi` `already_bound`/`tenant_conflict` mappings are retained
  defensively for version skew but no longer occur.

## Verified

- `go vet ./internal/auth/...` and `gofmt` clean;
  `go test ./internal/auth/...` pass.
- Migration applied live through the runner (`0073` ledgered after the
  drop-first fix).
- In-container against real capability roles, all six suites pass in
  one run, including the rewritten
  `TestPostgreSQLIdentityOrganizations`: second foundation succeeds
  with the tenant pinned to the first org, cross-org joins succeed
  without moving the primary tenant, two-org listings, switch to a
  membership with `OrgID` echo and continued validity, switches across
  memberships, `not_member`/unknown/revoked/expired switches refused,
  and the unchanged ten-table lockdown. Earlier suites prove the
  replaced sessions guard and the seven-column session lookup did not
  regress bootstrap, recovery, lockout, WebAuthn or HTTP flows.

## Limits

- No HTTP surface for switching yet (repository only); no switch audit
  beyond the row state, no per-org session caps, no primary-tenant
  change path, no invites/transfer/removal/service principals, no
  tenant-context wiring.

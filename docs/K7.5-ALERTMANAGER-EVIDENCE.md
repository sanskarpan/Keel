# K7.5 slice: local Alertmanager with generic webhook routing

Issue #464 follow-ups under #56 (K7.5 partial). PR #465 merged as `e99c860`; contract CI #733 passed on reviewed head `cb9cb79`. This slice adds a local
Alertmanager service with alert routing. No keys are committed and nothing pages yet. Owner direction 2026-11-01: PagerDuty removed as a dependency (cost); receivers post to a generic webhook URL the operator points at any free endpoint.

## Contract

- `deploy/monitoring/alertmanager/alertmanager.yaml`: critical receiver takes the two
  `critical` alerts, warning receiver takes the rest; grouping on fixed
  service/component/alertname labels only; WorkerDown inhibits warnings. Both receivers
  post to a generic webhook placeholder URL (`http://127.0.0.1:19094/hooks/ops-alerts`);
  delivery fails closed with log errors until the operator retargets it, and firing state
  stays visible in the Alertmanager UI.
- Compose runs Alertmanager pinned (v0.28.1) loopback-only with a single-node cluster
  address; Prometheus `alerting` points at it. Verified live: the container boots, gossips
  settle, and `/-/healthy` answers.
- `amtool check-config` passes; `promtool check config` passes with all 16 rules;
  Compose monitoring config validates.

## Limits

No delivery endpoint is configured: no integration keys, escalation policy, or production
deployment. Thresholds remain local starting points.

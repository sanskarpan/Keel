# K6.3 slice: quota policy operator API

Issue #431 (parent #48, checklist item K6.3). PR #432 merged as
`99b1d2b67d55aa7ff4bc68fed7d3ba3e8f2014d7`; contract CI #689 passed on reviewed head
`d54abb8ca65976e83af67b2458fa29ba71a81220`. This slice serves the tenant quota policy
setters on the unmounted operator API so operators no longer need raw SQL. No migration was
needed.

## Contract

- `POST /v1/webhooks/endpoint-limits` and `POST /v1/webhooks/delivery-limits` accept
  `change_id`, `limit`, `expected_version` and `reason`, derive tenant and actor from the
  trusted principal, validate through the existing change types, and return the durable policy
  version, limit and timestamp.
- A separate `CanManageWebhookPolicies` permission gates both routes, so replay and quota
  management can be granted independently; conflicts map to `policy_conflict`, invalid input to
  `invalid_request`, with no detail leaks.
- Coverage includes trusted-principal wiring, both setters, conflict/invalid/error mapping,
  malformed bodies, permission denial and an end-to-end handler-to-SQL test proving row writes,
  duplicate-change conflicts and versioned updates.

## Limits

No mounted route, production identity, global backlog caps, billing integration or automatic
over-cap remediation.

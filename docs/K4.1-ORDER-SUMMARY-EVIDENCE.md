# K4.1 `get_order_summary` bounded slice

Issue #184 implements one internal read-only tool under parent #31. It is not registered in a live model/runtime and does not complete K4.1.

The broker accepts only the fixed `get_order_summary` name and a bounded JSON object containing one canonical order UUID. It rejects duplicate/unknown fields, extra JSON values, malformed identifiers, unknown tool names, missing trusted principal context, and tenant mismatches. Authorization is a required injected fail-closed check and runs before the database reader. Principal and tenant context are server supplied; tool input cannot select either. `NewPrincipalFromVerifiedAuth` validates claim shape only; the future caller must source claims from verified authentication, since no identity provider/runtime is wired here.

The PostgreSQL reader is bound to one configured tenant agent role and executes one fixed query against `keel_meta.agent_order_summary`. Migration `0023` adds a `security_invoker` view, column-level base table grants, a `keel_agent` RLS policy, and no access to `tenant_id`, `command_snapshot`, or other private fields through the view. PostgreSQL derives tenant scope from the protected `session_user` mapping, so a caller-set tenant GUC cannot widen the view.

The tenant-bound database role is defense in depth, not principal/resource authorization. The injected order authorizer must use trusted identity and current resource grants; denying or failing authorization must prevent any lookup. Production identity and authorization providers remain unimplemented, so no route or model mount is included.

Rollback is a forward migration: disable the internal tool registration first, then apply a reviewed migration that revokes the view grant, drops the view and policy, and revokes the base column grants. Do not remove the session-user tenant mapping, which the existing K0 isolation gate also uses.

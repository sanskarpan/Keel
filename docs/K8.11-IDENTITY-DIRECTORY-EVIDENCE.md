# K8.11/K8.2 slice 16: directory reads and invite revocation over HTTP

Related to #70 and the K8.1/K8.2 tracks. Storage proved the directory
state; this slice serves it on three unmounted routes with the session
principal as the only actor. No route is mounted.

## Contract

- Migration `0078_identity_directory_reads`: capability-gated
  `members_for_organization` and `invites_for_organization` (rows only
  to `keel_identity` holders; unauthorized callers get empty sets) and
  `revoke_organization_invite` (`revoked` / `unknown_invite` /
  `not_authorized`; consumed invites stay immutable).
- `internal/auth/httpapi/directory.go`: `memberOf` pre-checks the
  caller's own membership list so strangers get `403` instead of an
  empty directory; `GET .../members` and `GET .../invites` return
  `200` with principal/role and invite/digest/role entries;
  `POST /v1/auth/invites/{invite_id}/revoke` returns `204`, `404`,
  `403`.
- `internal/auth/postgres`: `MembersFor` / `InvitesFor` (transparent
  rows) and `RevokeInvite` (`unknown_invite`→`ErrNotFound`,
  `not_authorized`→`ErrNotAuthorized`).

## Verified

- `go vet ./internal/auth/...` and `gofmt` clean;
  `go test ./internal/auth/...` pass, including mapping groups
  (member/invite listing with stranger/bad-org refusal, revoke
  outcomes).
- Migration applied live through the runner (`0078` ledgered).
- In-container against real capability roles:
  `--- PASS: TestPostgreSQLIdentityDirectory` — two-member listing
  with roles, empty pending list, stranger sees nothing at the
  function boundary, two invites listed, stranger revoke refused,
  revoke with repeat converging to unknown, consumed invite leaving
  the pending list; plus
  `--- PASS: TestHTTPDirectoryLifecycleAgainstPostgres` — owner
  list, stranger `403`, two invites, revoke with one remaining,
  repeat revoke `404`.
- All earlier suites pass in the same runs.

## Limits

- No routes mounted; invite digests are opaque hex (no address
  directory read model yet).
- No member search/filter/pagination beyond creation order, no
  demotion/removal endpoints, no audit trail.

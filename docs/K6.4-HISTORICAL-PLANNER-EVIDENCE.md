# K6.4 slice: historical planner

Issue #416 (parent #49, checklist item K6.4). PR #417 merged as
`f6f0c2828e3bebb5d42df734348008272465feec`; contract CI #669 passed on reviewed head
`f05d932e37cd0de2025951660d096f20710a926a`. This slice makes the dry-run planner count
missing deliveries against the endpoint status recorded at each event's time, so planned gaps
match exactly what historical repair can insert.

## Contract

- Migration `0060` re-creates `plan_webhook_reconciliation` with the same signature, capability,
  cursor accounting and return shape. The page scan crosses currently-active endpoints with the
  latest status-history record at or before each event's creation time: an endpoint counts as
  missing only when it was active then and no delivery exists at its then-current subscription.
  Inactive-then windows and pre-history events report no gap and create no gap rows.
- No Go changes: the planner API, validation and result shape are unchanged.
- Coverage proves an active/inactive/active three-event sequence plans gaps only for the two
  active-then events, and the repair slice's staged stale-gap case still audits its skip.

## Limits

No repair change, scheduler integration, reconciliation UI/metrics or HTTP exposure. Events
predating the status history report no gap and are never reconstructed.

# K6.2 Webhook signing, delivery identity and egress

Issue [#335](https://github.com/sanskarpan/Keel/issues/335) under parent [#46](https://github.com/sanskarpan/Keel/issues/46) fixes the outbound half of the webhook contract: every attempt is signed over the exact bytes it sends, every retry or replay can be deduplicated by a stable logical delivery identity, and no attempt can be steered into a private network.

## Wire contract

`internal/delivery/webhook` signs `HMAC-SHA256(secret, decimal_timestamp + "." + exact_body_bytes)` and emits one header:

```
Keel-Signature: t=1735689600,kid=key_2026_01,v1=d5cd4a4c95570419feaa5d6bb696ace7b589a5eb24387916b6296cc310f9c008
```

The header parser accepts exactly `t`, `kid` and `v1` in that order. Unknown, reordered, duplicated or non-canonical parts are rejected, as are a zero timestamp, a non-lowercase or wrong-length MAC and an out-of-pattern key ID. A receiver selects the secret by key ID, rebuilds the signing input from the exact body bytes it received, and compares in constant time.

An attempt also carries `Keel-Event-Id`, `Keel-Delivery-Id` and `Keel-Attempt-Id`. A retry or replay preserves the event ID and delivery ID, and changes the attempt ID, timestamp and signature.

## Keyring and rotation

A `Keyring` holds one active key and at most one previous key. A signature is accepted only when it names a held key, covers the exact body and sits inside a positive timestamp window (5 minutes by default, configurable per receiver). Unknown key, mismatch and skew are distinct errors, so a caller can log the reason without treating a forged attempt as a key-rotation problem.

`Rotated(next)` makes `next` active and retains the current active key as the previous one, so signatures issued just before a rotation still verify while new attempts use the new key. Rotating twice retires the oldest key, and rotating to the active key is rejected rather than silently accepted. The keyring copies secrets at construction, so a caller cannot mutate a key after validation.

## Logical delivery identity

The logical identity is `(tenant, event ID, endpoint ID, subscription revision)`. `Identity.Key()` renders a versioned, length-prefixed string, so a value cannot be shifted across a field boundary to collide with another identity. A delivery adds the stable delivery ID the receiver deduplicates on.

`Prepare` validates one attempt, signs a fresh timestamp and returns the four headers. A retry or replay calls `Prepare` again with a new attempt ID: the event, delivery and logical identity stay fixed, while the attempt ID and signature change. Tenant, event, endpoint, delivery and attempt fields are bounded by pattern and length, a zero tenant and a zero subscription revision are rejected, and subscription revisions are capped.

## SSRF-safe egress

`NewEgress` builds an HTTP client that never inherits environment proxies, requires TLS 1.2 or newer, and follows no redirect by default. `ValidateURL` rejects anything but `https`, any userinfo, a missing or single-label host, a trailing or leading dot, a zone identifier and a port outside the allowlist (443 unless configured).

Validation alone is not the control. `DialContext` resolves the host on every dial, denies the hostname if **any** answer is non-public, and dials the vetted numeric address itself. A second DNS answer, a rebinding host or a redirect to a private literal therefore cannot move the connection after validation. Redirects, when allowed, are re-validated and resolved again by the same policy.

The address classifier denies loopback, private, link-local, multicast, unspecified, CGNAT `100.64.0.0/10`, documentation, benchmark and reserved IPv4 ranges, plus the IPv6 unspecified/loopback/link-local/unique-local/multicast, NAT64 local-use, discard and documentation ranges. IPv4-mapped IPv6 addresses are classified as IPv4, so the mapped block never makes every IPv4 destination look reserved. A resolver failure is `ErrEgressUnavailable` (transient); a non-public or malformed destination is `ErrEgressDenied` (policy).

## Bounds and content

Key IDs, event IDs, endpoint IDs, delivery IDs and attempt IDs are bounded by pattern and length, secrets are at least 32 bytes, and the signature timestamp window is positive. The package handles no credentials, no request or response content and no tenant data beyond the identity fields; errors are fixed sentinels and never include a resolved address, hostname or secret.

## Validation

- Unit coverage: the known-answer signature vector above, strict header parsing (missing, extra, reordered, duplicated, zero, short, uppercase, whitespace), exact-body and tamper rejection, unknown key, timestamp boundaries, rotation overlap and retirement, secret copying, identity validation and key stability/collision, `Prepare` headers and replay semantics, and nil safety.
- Egress coverage: URL table (scheme, userinfo, host shape, port, zones, private literals), address-classifier table (including `169.254.169.254`, CGNAT, IPv4-mapped and IPv6 reserved forms), mixed public/private answers denied before dialing, per-dial re-resolution, port denial, resolver failure, address pinning, redirect budget and re-validation, and the client denying a loopback literal.
- `go test ./...` passes against the local PostgreSQL, Kafka, Redis and Temporal stack except the known Windows-only `internal/contracts` JSON-Schema path and `internal/supplier/intake` POSIX permission/symlink failures, which fail identically on `main`. `go vet ./...`, `go build ./...` and `gofmt -l` are clean.

## Limits

This is a code boundary. Nothing persists a delivery or attempt, no endpoint lifecycle or HTTP delivery worker exists, no retry, jitter or circuit breaker is wired, no key is stored or fetched from a KMS, and no runtime role uses the package. Retry and circuit breaking are K6.3, reconciliation and repairs are K6.4, adversarial late/duplicate/replay qualification is K6.5, and parent #46 stays open.

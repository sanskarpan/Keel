# K6.5 slice: provider callback observations

Issue #444 (parent #50, checklist item K6.5). This slice adds a code-owned synthetic provider
verifier for local development and tests, plus an append-only provider observation trail
recorded with every callback claim outcome. No production code paths change behavior.

## Contract

- Migration `0062` adds `provider_callback_observations` (identity-keyed outcome plus an
  optional redelivery delay, set on duplicates only) with forced RLS, revoked direct grants
  and an immutable-history trigger, plus a `keel_callback`-gated record function that rejects
  delays on non-duplicate outcomes.
- `SyntheticVerifier` authenticates one provider's callbacks with HMAC-SHA256 over
  `timestamp + "\n" + exact payload`, an RFC 3339 timestamp inside a five-minute skew window,
  a fixed JSON body (event type + occurrence time) and a static configured tenant mapping.
  Secrets under 32 bytes are rejected. It is explicitly not a production adapter.
- `Inbox.Accept` records one observation inside the claim transaction for each outcome
  (applied, duplicate with millisecond delay since application, conflict); a rolled-back
  application leaves no observation.
- Coverage includes verifier accept/tamper/skew/schema matrix, observation validation shapes,
  applied/duplicate/conflict trails, rollback emptiness, direct-access and immutability
  denial, and missing-capability rejection.

## Limits

No real provider adapter, late-callback business policy, observation reconciliation,
production wiring or mounted route. Owner deployment direction (Modal first, DigitalOcean as
the cheaper alternative, no AWS lock-in) is recorded in `docs/TECHNOLOGY-BASELINE.md`;
mounting approval and remaining owner decisions are recorded in the K6 gate audit.
